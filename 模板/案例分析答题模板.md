# 案例分析答题模板

## 通用审题步骤

1. 看系统背景：行业、用户量、关键业务、部署环境。
2. 找主要矛盾：性能不足、可靠性不足、安全风险、维护困难、扩展困难。
3. 定考查方向：架构风格、质量属性、数据库、分布式、安全、项目管理。
4. 用关键词作答：先写结论，再写措施，最后说明效果。

## 质量属性类问题

### 问法

系统需要重点关注哪些质量属性？应采取哪些措施？

### 答题结构

```text
应重点关注：性能、可用性、安全性、可维护性、可扩展性等。

针对性能，可采用缓存、异步处理、读写分离、索引优化、负载均衡等措施。
针对可用性，可采用集群、冗余、故障转移、健康检查、容灾备份等措施。
针对安全性，可采用认证授权、传输加密、存储加密、接口签名、审计日志等措施。
针对可维护性，可采用分层设计、模块化、接口隔离、配置化、统一日志等措施。
```

## 架构改进类问题

### 问法

现有架构有什么问题？如何改进？

### 答题结构

```text
现有问题包括：
1. 单点故障，影响系统可用性。
2. 同步调用链路过长，影响响应时间和稳定性。
3. 数据库压力集中，影响系统性能和扩展性。
4. 缺少统一认证、监控和日志，影响安全性和可运维性。

改进措施包括：
1. 引入负载均衡和集群部署，消除单点故障。
2. 对非实时任务使用消息队列异步处理，降低耦合并削峰填谷。
3. 对热点数据使用缓存，对数据库进行读写分离或分库分表。
4. 增加统一认证授权、链路追踪、监控告警和日志审计。
```

## 数据一致性类问题

### 问法

分布式场景下如何保证数据一致性？

### 答题结构

```text
如果业务要求强一致性，可使用本地事务、分布式事务或 TCC，但复杂度和性能成本较高。
如果业务允许短暂不一致，可使用可靠消息、事务消息、补偿机制、定时对账实现最终一致性。
同时需要保证接口幂等，设置重试、超时和异常处理机制，避免重复扣减、重复提交等问题。
```

## 安全类问题

### 问法

系统存在哪些安全风险？如何保证接口和数据安全？

### 答题结构

```text
主要风险包括：未授权访问、敏感数据泄露、接口被篡改、重放攻击、SQL 注入、日志缺失等。

可采取以下措施：
1. 使用统一身份认证和权限控制，按最小权限授权。
2. 使用 HTTPS 保护传输过程，对敏感数据进行存储加密或脱敏。
3. 对接口请求增加签名、时间戳和随机数，防止篡改和重放。
4. 对输入参数进行校验，防止注入攻击。
5. 记录关键操作日志和安全审计日志，便于追踪。
```

## 性能优化类问题

### 问法

系统访问量增长后如何优化？

### 答题结构

```text
应先定位瓶颈，再针对性优化。常见瓶颈包括应用服务器、数据库、缓存、网络和外部接口。

应用层可通过无状态化、水平扩展、负载均衡、异步处理提升吞吐量。
数据层可通过索引优化、读写分离、分库分表、冷热数据分离降低数据库压力。
缓存层可缓存热点数据，并处理缓存穿透、击穿和雪崩问题。
运维层应增加监控告警、容量评估和压测，持续验证优化效果。
```
