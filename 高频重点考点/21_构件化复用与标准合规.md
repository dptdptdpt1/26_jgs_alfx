# 构件化复用与标准合规

> 重要程度：P2  
> 考纲定位：软件复用、标准规范、设计文档和信息技术标准。

## 优先掌握

1. 构件、模块、服务、平台的区别。
2. 可复用构件的接口、契约、版本和文档。
3. 复用的收益和成本。
4. 标准合规：接口、数据、安全、日志、运维和开发规范。

## 概念和场景

| 重要度 | 内容 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | 构件 | 可独立复用的软件单元 | 统一短信发送构件被多个业务系统调用 |
| P0 | 接口契约 | 调用双方遵守的输入、输出和错误约定 | 支付接口明确金额、订单号、签名和返回码 |
| P0 | 版本管理 | 控制构件或接口演进 | 新增字段不影响旧客户端，旧版本保留一段时间 |
| P0 | 数据标准 | 统一数据命名、编码和口径 | 客户编号、组织编码在全系统一致 |
| P1 | 构件库 | 管理构件资产和复用信息 | 团队从构件库查找统一认证组件 |
| P1 | 黑盒复用 | 不改内部实现，只按接口使用 | 调用第三方地图服务 |
| P1 | 白盒复用 | 可修改内部实现后复用 | 复制通用报表组件并适配业务 |
| P1 | 合规 | 满足法规、标准和组织规范 | 日志保留期限、隐私脱敏、安全审计符合要求 |

## 复用设计规则

1. 接口稳定，内部实现可替换。
2. 职责单一，不把多个无关能力塞进一个构件。
3. 文档清楚：用途、接口、异常、版本、依赖、示例。
4. 有测试和质量门禁，复用不能传播缺陷。
5. 有版本和兼容策略，避免升级破坏调用方。

## 标准合规答题点

| 领域 | 要点 |
| --- | --- |
| 接口标准 | 命名、协议、参数、错误码、版本、鉴权。 |
| 数据标准 | 编码、主数据、元数据、指标口径、质量规则。 |
| 安全标准 | 认证授权、加密、审计、最小权限、隐私保护。 |
| 运维标准 | 日志格式、指标、告警、备份、发布流程。 |
| 开发标准 | 代码规范、评审、测试、配置管理。 |

## 易混点

| 易混项 | 区分 |
| --- | --- |
| 构件 vs 服务 | 构件强调可复用软件单元；服务强调通过接口对外提供能力。 |
| 复用 vs 复制 | 复用有稳定接口和治理；复制容易形成多份不可控代码。 |
| 标准化 vs 灵活性 | 标准化降低协作成本，但过度标准化会限制业务变化。 |

## 边界

不展开具体国家标准条文；案例题重点是“为什么要标准化、标准化哪些对象、如何治理”。
