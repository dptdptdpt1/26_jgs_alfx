# 需求分析与建模

> 重要程度：P0  
> 考纲定位：软件系统建模、需求规格说明、架构设计输入。

## 优先掌握

1. 功能需求、非功能需求、约束和业务规则的区分。
2. 用例图、类图、顺序图、活动图、状态图、DFD、ER 图的适用场景。
3. 需求变更对架构、数据、接口、测试和项目计划的影响。
4. 建模题补图时的边界、关系、流向和一致性检查。

## 概念和场景

| 重要度 | 内容 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | 功能需求 | 系统必须做什么 | 用户下单、管理员审核、系统生成报表 |
| P0 | 非功能需求 | 系统做得怎么样 | 订单查询 1 秒内返回，系统全年可用率 99.9% |
| P0 | 约束 | 对方案的限制条件 | 必须使用国产数据库，必须部署在内网 |
| P0 | 业务规则 | 业务自身的判断规则 | 退款金额不得超过实付金额 |
| P0 | 用例图 | 描述参与者和系统目标 | 判断哪些角色能发起哪些业务 |
| P0 | 类图 | 描述对象结构和关系 | 订单、订单明细、商品、支付单之间的关联 |
| P0 | 顺序图 | 描述对象之间的时序调用 | 用户提交订单后，订单服务依次调用库存和支付 |
| P1 | 活动图 | 描述业务流程和分支 | 采购申请经过提交、审批、驳回或归档 |
| P1 | 状态图 | 描述对象生命周期 | 订单从待支付到已支付、已取消、已完成 |
| P1 | DFD | 描述数据流动和加工 | 外部客户提交申请，系统校验后写入申请库 |
| P1 | ER 图 | 描述实体、属性和联系 | 学生、课程、选课记录的多对多关系 |

## 建模题答题顺序

1. 先找边界：系统外部角色、外部系统、输入输出。
2. 再找核心对象：名词通常对应实体、类或数据存储。
3. 再找动作和流程：动词通常对应用例、加工或消息。
4. 最后检查一致性：名称一致、方向一致、多重度合理、分层平衡。

## 常见补图规则

| 图 | 检查重点 |
| --- | --- |
| 用例图 | 参与者在系统外；include 是必做复用，extend 是条件扩展。 |
| 类图 | 组合强生命周期绑定，聚合弱整体-部分，关联只表示知道或使用。 |
| 顺序图 | 消息顺序要符合题干流程；同步调用要有返回或后续处理。 |
| DFD | 父图和子图输入输出要平衡；数据流不能直接从外部实体到数据存储。 |
| ER 图 | 多对多通常要拆中间实体；属性不要错画成实体。 |

## 易混点

| 易混项 | 区分 |
| --- | --- |
| 非功能需求 vs 约束 | 非功能需求是质量目标；约束是设计时必须遵守的限制。 |
| 活动图 vs 顺序图 | 活动图看流程控制；顺序图看对象交互时序。 |
| 状态图 vs 活动图 | 状态图围绕一个对象状态变化；活动图围绕业务流程。 |
