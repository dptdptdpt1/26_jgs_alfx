# 通信与网络架构

> 重要程度：P1  
> 考纲定位：计算机网络基础、通信系统架构、安全边界和高可用部署。

## 优先掌握

1. 网络分区：外网、DMZ、内网、管理区、数据区。
2. DNS、负载均衡、反向代理、网关的角色。
3. TCP、UDP、HTTP、HTTPS、WebSocket 的适用场景。
4. 网络高可用和安全边界设计。

## 概念和场景

| 重要度 | 内容 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | DMZ | 外网和内网之间的缓冲区 | Web 服务器放 DMZ，数据库不直接暴露外网 |
| P0 | 负载均衡 | 分发请求到多个后端 | 多台应用服务器共同承接用户请求 |
| P0 | 反向代理 | 代表后端接收客户端请求 | Nginx 接入请求并转发到应用集群 |
| P0 | VPN | 在不可信网络上建立加密通道 | 分支机构通过 VPN 访问总部内网系统 |
| P0 | HTTPS/TLS | 加密传输并校验证书 | 用户登录和支付接口必须使用 HTTPS |
| P1 | TCP | 面向连接、可靠传输 | 订单提交、文件上传要求可靠传输 |
| P1 | UDP | 无连接、低延迟 | 音视频、实时监控可容忍少量丢包 |
| P1 | WebSocket | 客户端和服务端保持双向通信 | 实时消息、在线客服、行情推送 |

## 网络分区答题模板

1. 外网入口：DNS、CDN、负载均衡或 WAF。
2. DMZ：放置 Web、网关、反向代理等需对外服务的组件。
3. 应用区：部署业务服务，只允许必要端口访问。
4. 数据区：数据库、缓存、文件存储，不直接暴露外网。
5. 管理区：运维堡垒机、监控、日志、备份。
6. 安全控制：防火墙、访问控制、审计、入侵检测。

## 高可用网络设计

| 场景 | 处理 |
| --- | --- |
| 单链路故障 | 双线路、链路冗余、自动切换。 |
| 单负载均衡故障 | 负载均衡集群或主备。 |
| 单机房故障 | 同城双活、异地灾备、DNS 切流。 |
| 网络攻击 | WAF、DDoS 防护、限流、黑白名单。 |

## 易混点

| 易混项 | 区分 |
| --- | --- |
| VPN vs HTTPS | VPN 保护网络通道；HTTPS 保护应用层会话。 |
| 正向代理 vs 反向代理 | 正向代理代表客户端；反向代理代表服务端。 |
| 南北向 vs 东西向流量 | 南北向是外部与系统间流量；东西向是内部服务间流量。 |

## 边界

不展开路由协议细节和设备命令；案例题重点是分区、访问路径、冗余和安全控制。
