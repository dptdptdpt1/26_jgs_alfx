# 系统计划与方案评估

## 考试中一般怎么考

1. 可行性分析：要求从技术、经济、运行、法律、进度等角度判断项目是否可行。
2. 方案比较：给多个技术方案，要求比较优缺点、风险和适用场景。
3. 新旧系统比较：问是否替换、改造、集成或渐进迁移。
4. 资源复用：问如何利用已有软件、硬件、数据和接口，降低成本和风险。
5. 改进建议：根据现有系统问题提出架构、数据、性能、安全和运维改进。

## 针对考法梳理知识点

### 可行性分析

| 角度 | 看什么 |
| --- | --- |
| 技术可行性 | 技术成熟度、团队能力、系统复杂度、集成难度 |
| 经济可行性 | 建设成本、运维成本、收益、投资回收期 |
| 运行可行性 | 组织流程、用户接受度、培训和运维能力 |
| 法律合规 | 数据安全、隐私、知识产权、行业监管 |
| 进度可行性 | 工期、资源、关键依赖、交付风险 |

答题不要只写“可行”。要指出可行的依据和主要风险。

### 方案比较

方案题建议按同一维度比较：

- 功能满足度。
- 性能、可用性、安全性、可扩展性。
- 技术成熟度和团队掌握程度。
- 与现有系统集成难度。
- 建设成本和运维成本。
- 迁移风险和回滚能力。

如果题目要求“推荐方案”，要先说明业务目标，再说明为什么该方案更匹配目标。

### 新旧系统处理策略

| 策略 | 适合场景 | 风险 |
| --- | --- | --- |
| 直接替换 | 旧系统价值低、数据简单、停机窗口允许 | 切换风险高 |
| 渐进迁移 | 业务复杂、停机成本高、需要平滑过渡 | 双系统并行复杂 |
| 外围扩展 | 核心旧系统稳定但扩展困难 | 旧系统仍是瓶颈 |
| 集成保留 | 旧系统仍承载关键能力 | 接口治理和数据一致性复杂 |

常见答题点：先保留关键业务连续性，再逐步迁移低风险模块，最后迁移核心模块。

### 现有资源利用

可复用资源：

- 硬件资源：服务器、网络、存储、机房、云资源。
- 软件资源：已有业务系统、中间件、统一认证、报表平台。
- 数据资源：历史数据、主数据、指标口径。
- 接口资源：已有服务接口、消息通道、数据交换平台。
- 运维资源：监控、日志、发布流水线、备份体系。

易错点：复用不是无条件复用。旧资源如果性能不足、安全不达标或接口不可治理，应改造后再接入。

### 成本收益分析

成本包括：

- 一次性建设成本。
- 软硬件和云资源成本。
- 数据迁移和接口改造成本。
- 培训、运维和安全合规成本。

收益包括：

- 提升处理效率。
- 降低人工成本和故障损失。
- 改善用户体验。
- 支撑业务扩展和监管要求。

### 方案评估答题模板

```text
先明确业务目标和约束，再从技术、经济、运行、合规、进度维度评估方案；比较各方案在质量属性、集成难度、成本和风险上的差异；优先选择满足核心目标且风险可控的方案；对迁移、数据一致性、安全合规和回滚制定配套措施。
```
