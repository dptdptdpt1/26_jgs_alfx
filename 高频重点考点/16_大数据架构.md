# 大数据架构

## 考试中一般怎么考

1. 架构选型：给出海量数据、实时分析、离线报表场景，要求选择数仓、数据湖、流处理或混合架构。
2. 数据链路：要求说明数据采集、清洗、存储、计算、分析、展示的流程。
3. 离线与实时：区分批处理、流处理、Lambda、Kappa 架构。
4. 数据治理：问数据质量、元数据、血缘、权限、口径一致性如何保证。
5. 性能与成本：问海量数据下如何分区、压缩、冷热分层、弹性扩展。

## 针对考法梳理知识点

### 大数据系统的典型链路

常见链路：

```text
数据源 -> 采集接入 -> 清洗转换 -> 存储 -> 计算 -> 服务/API/报表 -> 数据应用
```

答题不要只写“使用大数据平台”，要说明数据从哪里来、如何处理、存到哪里、如何计算、最终服务什么业务。

### 数据仓库和数据湖

| 方案 | 适合场景 | 答题要点 |
| --- | --- | --- |
| 数据仓库 | 结构化数据、稳定报表、统一指标 | 建模规范、口径一致、查询性能好 |
| 数据湖 | 多源异构数据、原始数据保留、探索分析 | 先存后用、支持结构化和非结构化数据 |
| 湖仓一体 | 既要低成本存储，又要分析性能和治理能力 | 统一存储、事务能力、元数据和权限治理 |

易错点：数据湖不是“什么都往里扔就完了”。没有元数据、权限、质量和生命周期管理，会变成数据沼泽。

### 离线处理和实时处理

| 类型 | 特点 | 常见场景 |
| --- | --- | --- |
| 离线批处理 | 按小时/天批量计算，吞吐高，延迟高 | 日报、月报、历史统计 |
| 实时流处理 | 数据到达后持续计算，延迟低 | 实时风控、监控告警、实时大屏 |
| 准实时处理 | 分钟级延迟，成本和复杂度适中 | 运营看板、搜索索引更新 |

如果题目强调“当天报表、历史趋势”，优先离线；强调“秒级告警、实时拦截”，优先流处理。

### Lambda 和 Kappa 架构

| 架构 | 核心思路 | 代价 |
| --- | --- | --- |
| Lambda | 批处理保证准确性，流处理保证实时性，最终合并结果 | 两套链路，开发和维护成本高 |
| Kappa | 只保留流处理链路，历史数据通过重放日志重新计算 | 对消息日志保存和重放能力要求高 |

答题时要写清取舍：Lambda 适合既要实时又要离线校准的复杂场景；Kappa 适合逻辑统一、实时链路能力强的场景。

### 数据建模和指标口径

数据分析题常见问题不是算不动，而是口径不一致。

常见措施：

- 建立统一指标字典，明确指标定义、维度、统计周期。
- 分层建模，例如 ODS、DWD、DWS、ADS。
- 关键数据保留血缘关系，能追踪指标来自哪些源表和转换逻辑。
- 对重要报表建立数据校验和对账机制。

### 数据质量治理

常见质量问题：

- 缺失值、重复数据、异常值。
- 编码不统一，例如地区、机构、商品分类口径不同。
- 数据延迟，导致报表不完整。
- 上游字段变更，下游任务失败或结果错误。

常见治理措施：

- 采集和清洗阶段做格式校验、去重、补全、异常过滤。
- 对核心字段设置质量规则和告警。
- 建立元数据管理和数据血缘。
- 重要指标做对账和抽样核验。

### 存储和查询优化

海量数据优化常用做法：

- 按时间、地区、业务类型分区，减少扫描范围。
- 列式存储适合分析查询，压缩率高。
- 冷热分层，热数据放高性能存储，冷数据低成本归档。
- 预聚合或物化视图提升高频指标查询速度。
- 对明细查询、全文检索、复杂搜索使用专门引擎。

易错点：不能把所有查询都交给一个数据库。分析型查询、明细检索、实时查询的存储和计算方式通常不同。

### 大数据架构答题模板

可以按固定顺序写：

```text
先通过采集组件接入业务库、日志和外部数据；进入 ODS 保留原始数据；经过清洗、去重、标准化后进入明细层和汇总层；离线任务生成周期报表，实时流处理支撑告警和大屏；通过统一指标口径、元数据、血缘、权限和质量校验保证数据可用；通过分区、列式存储、冷热分层和预聚合控制性能与成本。
```
