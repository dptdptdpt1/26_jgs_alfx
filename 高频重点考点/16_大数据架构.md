# 大数据架构

## 考试中一般怎么考

1. 架构选型：给出海量数据、实时分析、离线报表场景，要求选择数仓、数据湖、流处理或混合架构。
2. 数据链路：要求说明数据采集、清洗、存储、计算、分析、展示的流程。
3. 数仓建模：问 ODS、DWD、DWS、ADS 分层，事实表、维度表和指标口径。
4. 离线与实时：区分批处理、流处理、Lambda、Kappa 架构。
5. 数据治理：问数据质量、元数据、血缘、权限、口径一致性如何保证。
6. 数据安全：问数据分级分类、脱敏、加密、审计和最小权限。
7. 性能与成本：问海量数据下如何分区、压缩、冷热分层、弹性扩展、小文件和数据倾斜。

## 针对考法梳理知识点

### 大数据 5V 特征

大数据通常用 5V 描述：

| 特征 | 含义 |
| --- | --- |
| Volume | 数据量大 |
| Velocity | 产生和处理速度快 |
| Variety | 数据类型多，包括结构化、半结构化、非结构化 |
| Value | 价值密度低，需要挖掘 |
| Veracity | 数据真实性和质量参差不齐 |

考试里如果问“为什么传统数据库难以支撑”，可以从数据规模、类型多样、实时处理、复杂分析和成本扩展角度回答。

### 大数据系统的典型链路

常见链路：

```text
数据源 -> 采集接入 -> 清洗转换 -> 存储 -> 计算 -> 服务/API/报表 -> 数据应用
```

答题不要只写“使用大数据平台”，要说明数据从哪里来、如何处理、存到哪里、如何计算、最终服务什么业务。

### 数据采集方式

常见数据源和采集方式：

| 方式 | 说明 | 适用 |
| --- | --- | --- |
| 业务库同步 | 从 MySQL、Oracle 等同步业务表 | 订单、用户、交易等结构化数据 |
| CDC | 捕获数据库增量变更 | 准实时同步、降低全量抽取压力 |
| 日志采集 | 采集应用日志、访问日志、设备日志 | 行为分析、故障分析、监控 |
| 埋点数据 | 前端、App 或服务端记录用户行为 | 用户路径、转化率、运营分析 |
| 消息队列 | 通过事件流接入实时数据 | 实时计算、实时大屏、风控 |
| 文件导入 | 批量导入 CSV、Excel、压缩文件 | 外部数据、历史数据 |
| API 接入 | 调用外部接口获取数据 | 第三方数据、低频同步 |

采集设计要关注全量和增量、数据延迟、失败重试、重复数据、字段变更和数据校验。

### ETL 和 ELT

| 对比 | ETL | ELT |
| --- | --- | --- |
| 顺序 | 抽取、转换、加载 | 抽取、加载、转换 |
| 特点 | 入库前完成清洗转换 | 先保留原始数据，再在平台内加工 |
| 适用 | 规则明确、目标模型稳定 | 数据湖、探索分析、计算资源充足 |

数据仓库传统上常用 ETL。数据湖和湖仓场景常用 ELT，因为先保留原始数据，后续可以按不同需求反复加工。

### OLTP 和 OLAP

| 对比 | OLTP | OLAP |
| --- | --- | --- |
| 目标 | 在线交易处理 | 在线分析处理 |
| 关注 | 事务一致性、低延迟、高并发 | 复杂查询、多维分析、批量扫描 |
| 数据 | 当前业务数据为主 | 历史、汇总、多源数据 |
| 场景 | 下单、支付、库存扣减 | 报表、指标分析、经营决策 |

不要直接在业务库上跑复杂统计。它会影响交易性能，也难以整合历史和多源数据。

### 数据仓库和数据湖

| 方案 | 适合场景 | 答题要点 |
| --- | --- | --- |
| 数据仓库 | 结构化数据、稳定报表、统一指标 | 建模规范、口径一致、查询性能好 |
| 数据湖 | 多源异构数据、原始数据保留、探索分析 | 先存后用、支持结构化和非结构化数据 |
| 湖仓一体 | 既要低成本存储，又要分析性能和治理能力 | 统一存储、事务能力、元数据和权限治理 |

易错点：数据湖不是“什么都往里扔就完了”。没有元数据、权限、质量和生命周期管理，会变成数据沼泽。

### 湖仓一体特征

湖仓一体试图同时获得数据湖的低成本和数据仓库的治理、性能能力。

常见特征：

- 统一存储，支持结构化、半结构化和非结构化数据。
- 开放数据格式，减少平台绑定。
- 支持事务、Schema 管理和数据版本。
- 支持批处理和流处理。
- 统一元数据、权限和数据血缘。
- 支持面向分析的查询优化。

答题时可写：湖仓一体适合既要保留多源原始数据，又要支撑规范化分析和统一治理的场景。

### 数据湖治理

数据湖如果缺少治理，会变成数据沼泽。

治理重点：

- 数据目录：让用户知道有哪些数据、在哪里、谁负责。
- 元数据：记录表、字段、分区、格式、来源和更新时间。
- 数据质量：校验完整性、唯一性、准确性和及时性。
- 权限控制：按数据域、表、字段和敏感级别控制访问。
- 生命周期：热数据、温数据、冷数据分层保存和归档。
- 血缘关系：追踪数据从源头到报表的加工链路。

### 离线处理和实时处理

| 类型 | 特点 | 常见场景 |
| --- | --- | --- |
| 离线批处理 | 按小时/天批量计算，吞吐高，延迟高 | 日报、月报、历史统计 |
| 实时流处理 | 数据到达后持续计算，延迟低 | 实时风控、监控告警、实时大屏 |
| 准实时处理 | 分钟级延迟，成本和复杂度适中 | 运营看板、搜索索引更新 |

如果题目强调“当天报表、历史趋势”，优先离线；强调“秒级告警、实时拦截”，优先流处理。

### 批处理和流处理细化

批处理适合大规模历史数据计算，吞吐高但延迟高。常见问题是任务调度、依赖管理、失败重跑和数据校验。

流处理适合低延迟场景，数据到达后持续计算。常见问题是状态管理、窗口计算、乱序数据、迟到数据和精确一次语义。

流处理常见概念：

- 窗口：按时间或数量把连续数据切成计算范围。
- 事件时间：事件实际发生时间。
- 处理时间：系统处理事件的时间。
- 乱序数据：晚到的数据时间早于已处理数据。
- 水位线：判断某个时间之前的数据基本到齐。

实时题如果问“为什么结果会变动”，常见原因是迟到数据、乱序数据和窗口更新。

### 常见大数据组件

| 组件 | 作用 |
| --- | --- |
| HDFS | 分布式文件存储，适合大文件和离线数据 |
| Hive | 数据仓库 SQL 分析，适合离线报表 |
| Spark | 批处理、内存计算、机器学习等通用计算 |
| Flink | 低延迟流处理和有状态计算 |
| Kafka | 高吞吐消息日志，适合实时数据接入 |
| HBase | 分布式列族数据库，适合海量明细随机读写 |
| Elasticsearch | 全文检索、日志检索和复杂搜索 |

考试不必纠结产品细节，重点是把“存储、采集、离线计算、实时计算、查询服务”的职责分清。

### 实时数仓

实时数仓用于支撑秒级或分钟级指标、告警和大屏。

常见链路：

```text
业务事件 / 日志 -> Kafka -> Flink 清洗聚合 -> 实时明细 / 汇总 -> 查询服务 / 大屏 / 告警
```

常见场景：

- 实时交易大屏。
- 实时风控。
- 实时监控告警。
- 实时推荐特征更新。

实时数仓要处理消息重复、乱序、迟到、状态保存、失败恢复和指标口径一致。

### Lambda 和 Kappa 架构

| 架构 | 核心思路 | 代价 |
| --- | --- | --- |
| Lambda | 批处理保证准确性，流处理保证实时性，最终合并结果 | 两套链路，开发和维护成本高 |
| Kappa | 只保留流处理链路，历史数据通过重放日志重新计算 | 对消息日志保存和重放能力要求高 |

答题时要写清取舍：Lambda 适合既要实时又要离线校准的复杂场景；Kappa 适合逻辑统一、实时链路能力强的场景。

### 数据建模和指标口径

数据分析题常见问题不是算不动，而是口径不一致。

常见措施：

- 建立统一指标字典，明确指标定义、维度、统计周期。
- 分层建模，例如 ODS、DWD、DWS、ADS。
- 关键数据保留血缘关系，能追踪指标来自哪些源表和转换逻辑。
- 对重要报表建立数据校验和对账机制。

### 数仓分层

常见数仓分层：

| 层次 | 作用 |
| --- | --- |
| ODS | 原始数据层，尽量保留源系统原貌 |
| DWD | 明细数据层，完成清洗、标准化、去重和明细建模 |
| DWS | 汇总数据层，按主题或业务过程形成公共汇总 |
| ADS | 应用数据层，面向报表、看板、接口和业务应用 |

分层的作用：

- 降低重复开发。
- 统一数据口径。
- 便于复用和追踪血缘。
- 隔离源系统变化对上层应用的影响。

### 维度建模

维度建模面向分析查询，核心是事实表和维度表。

| 概念 | 含义 |
| --- | --- |
| 事实表 | 记录业务过程中的度量值，例如订单金额、支付次数 |
| 维度表 | 描述分析角度，例如时间、地区、用户、商品 |
| 星型模型 | 一个事实表直接关联多个维度表，查询简单 |
| 雪花模型 | 维度继续规范化拆分，冗余少但查询更复杂 |
| 宽表 | 把常用维度和指标预先打宽，提升查询效率 |

例子：订单分析中，订单事实表保存订单金额、数量、支付时间，用户维度、商品维度、地区维度用于按不同角度统计。

### 指标体系

指标要有统一定义，否则不同部门报表会不一致。

常见概念：

- 原子指标：不可再拆的基础度量，例如支付金额、订单数。
- 派生指标：原子指标加统计周期、维度和过滤条件，例如最近 7 天支付金额。
- 复合指标：由多个指标计算得到，例如转化率、客单价。
- 维度：观察指标的角度，例如地区、渠道、商品类目。
- 统计周期：日、周、月、实时窗口等。

指标定义要明确口径、数据来源、过滤条件、统计时间和负责人。

### 数据集市

数据集市是面向某个部门、主题或业务场景的数据子集。

例子：

- 销售数据集市。
- 财务数据集市。
- 风控数据集市。
- 用户运营数据集市。

数据集市通常基于统一数仓建设，避免各部门各自加工导致口径不一致。

### 数据质量治理

常见质量问题：

- 缺失值、重复数据、异常值。
- 编码不统一，例如地区、机构、商品分类口径不同。
- 数据延迟，导致报表不完整。
- 上游字段变更，下游任务失败或结果错误。

常见治理措施：

- 采集和清洗阶段做格式校验、去重、补全、异常过滤。
- 对核心字段设置质量规则和告警。
- 建立元数据管理和数据血缘。
- 重要指标做对账和抽样核验。

### 数据治理体系

数据治理是让数据可找、可信、可用、可控。

常见内容：

| 治理项 | 作用 |
| --- | --- |
| 数据标准 | 统一编码、命名、字段含义和指标口径 |
| 元数据管理 | 管理表、字段、任务、分区、负责人和更新时间 |
| 数据质量 | 校验完整性、准确性、一致性、及时性 |
| 数据血缘 | 追踪数据来源、加工过程和下游影响 |
| 主数据管理 | 统一客户、产品、组织等核心数据 |
| 数据安全 | 分级分类、权限、脱敏、加密和审计 |
| 生命周期 | 控制数据保留、归档和销毁 |

案例题中如果出现“找不到数据、口径不一致、报表不可信、字段变更影响下游”，优先从治理体系回答。

### 数据血缘和影响分析

数据血缘描述数据从源系统到报表指标的流转和加工链路。

作用：

- 指标出错时追踪来源和转换逻辑。
- 上游字段变更时分析影响哪些任务、表和报表。
- 支持审计和责任定位。
- 帮助理解数据资产和复用关系。

答题可写：建立字段级和表级血缘，配合任务调度、元数据和变更管理做影响分析。

### 数据安全和隐私

大数据平台集中存储大量数据，安全治理很重要。

常见措施：

- 数据分级分类：按敏感程度划分公开、内部、敏感、核心等等级。
- 权限控制：按角色、部门、项目、表、列、行控制访问。
- 数据脱敏：手机号、身份证、地址等敏感字段展示或开发测试时脱敏。
- 加密：传输加密和存储加密。
- 审计：记录谁在什么时间访问了什么数据。
- 数据水印：追踪数据泄露来源。
- 最小权限：只授予完成工作所需的数据权限。

考试中不要只写“加权限”。要结合分级分类、脱敏、加密、审计和最小权限。

### 存储和查询优化

海量数据优化常用做法：

- 按时间、地区、业务类型分区，减少扫描范围。
- 列式存储适合分析查询，压缩率高。
- 冷热分层，热数据放高性能存储，冷数据低成本归档。
- 预聚合或物化视图提升高频指标查询速度。
- 对明细查询、全文检索、复杂搜索使用专门引擎。

易错点：不能把所有查询都交给一个数据库。分析型查询、明细检索、实时查询的存储和计算方式通常不同。

### 冷热分层和生命周期

按访问频率和价值管理数据：

| 类型 | 特点 | 存储策略 |
| --- | --- | --- |
| 热数据 | 最近、频繁访问 | 高性能存储，支持快速查询 |
| 温数据 | 偶尔访问 | 普通存储，成本和性能平衡 |
| 冷数据 | 很少访问，但需保留 | 低成本归档存储 |

生命周期管理要明确数据保留周期、归档规则、删除规则和合规要求。不是所有历史数据都应该长期放在高性能存储上。

### 常见性能问题

| 问题 | 表现 | 优化 |
| --- | --- | --- |
| 小文件过多 | 元数据压力大，任务启动慢 | 合并小文件、批量写入、控制分区粒度 |
| 数据倾斜 | 少数任务特别慢 | 加盐、拆分热点 Key、预聚合、调整分区 |
| 分区过多 | 查询和元数据管理变慢 | 合理设计分区字段和粒度 |
| 扫描数据过多 | 查询慢、成本高 | 分区裁剪、列式存储、谓词下推 |
| 重复计算 | 资源浪费 | 公共中间层、预聚合、物化视图 |

大数据性能优化通常先看扫描量、分区、文件大小、Shuffle、热点 Key 和任务并行度。

### 大数据架构答题模板

可以按固定顺序写：

```text
先通过采集组件接入业务库、日志和外部数据；进入 ODS 保留原始数据；经过清洗、去重、标准化后进入明细层和汇总层；离线任务生成周期报表，实时流处理支撑告警和大屏；通过统一指标口径、元数据、血缘、权限和质量校验保证数据可用；通过分区、列式存储、冷热分层和预聚合控制性能与成本。
```
