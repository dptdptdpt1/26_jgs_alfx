# 系统集成与中间件

> 重要程度：P1  
> 考纲定位：主流中间件、应用支撑技术、系统集成和服务化设计。

## 优先掌握

1. 同步调用、异步消息、批量交换和共享数据库的取舍。
2. RPC、REST、WebService、消息队列、ESB 的适用场景。
3. 消息可靠性：投递、消费、幂等、重试、死信、对账。
4. 接口契约、版本管理、安全和监控。

## 概念和场景

| 重要度 | 内容 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | 同步调用 | 调用方等待结果 | 订单提交时同步校验库存是否足够 |
| P0 | 异步消息 | 发送消息后由消费者后续处理 | 下单成功后异步发短信、加积分 |
| P0 | REST | 以资源为中心的 HTTP 接口风格 | 对外开放订单查询接口 |
| P0 | 消息队列 | 解耦、削峰、异步处理的中间件 | 大促订单先入队，后台按能力消费 |
| P1 | RPC | 面向过程或服务方法的远程调用 | 内部服务之间低延迟调用 |
| P1 | WebService | 基于标准协议的服务集成 | 与旧系统或跨组织系统按标准接口对接 |
| P1 | ESB | 企业服务总线，统一协议转换和路由 | 多个遗留系统通过总线集成 |
| P1 | 适配器 | 屏蔽外部系统差异 | 新系统用统一接口调用不同厂商接口 |

## 集成方式选择

| 场景 | 选择 |
| --- | --- |
| 必须立即得到结果 | 同步调用，配合超时、重试、熔断。 |
| 非核心链路或可延后处理 | 异步消息，配合可靠投递和幂等消费。 |
| 多旧系统、协议不统一 | ESB 或适配器，配合接口标准治理。 |
| 大批量离线数据交换 | 文件、ETL 或批处理接口，配合校验和对账。 |
| 外部开放能力 | REST/API 网关，配合鉴权、限流和审计。 |

## 消息可靠性闭环

1. 生产端确认消息发送成功。
2. Broker 持久化消息。
3. 消费端成功处理后再确认。
4. 消费失败可重试，超过阈值进入死信队列。
5. 消费逻辑必须幂等。
6. 用对账或补偿任务处理异常遗漏。

## 易混点

| 易混项 | 区分 |
| --- | --- |
| API 网关 vs ESB | API 网关偏外部入口和流量治理；ESB 偏企业内部系统集成和协议转换。 |
| RPC vs REST | RPC 偏内部方法调用；REST 偏资源和开放接口。 |
| 异步 vs 最终一致 | 异步是交互方式；最终一致是数据一致性目标。 |

## 考纲外重要保留

Kafka、RabbitMQ、RocketMQ 等具体产品不展开；只保留通用消息能力和可靠性机制。
