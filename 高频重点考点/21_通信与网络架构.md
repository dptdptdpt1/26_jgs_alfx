# 通信与网络架构

## 考试中一般怎么考

1. 网络拓扑：要求设计内外网、DMZ、负载均衡、防火墙、专线或 VPN。
2. 通信协议：问 HTTP、HTTPS、TCP、UDP、MQTT、WebSocket 等如何选择。
3. 网络安全：问边界防护、访问控制、传输加密、入侵检测。
4. 高可用网络：问链路冗余、设备冗余、故障切换和流量调度。
5. 性能优化：问带宽、延迟、QoS、CDN、边缘节点如何处理。

## 针对考法梳理知识点

### 网络分区

常见分区：

- 外网区：用户或外部系统访问入口。
- DMZ 区：放置 Web、网关、反向代理等对外服务。
- 应用区：部署业务服务。
- 数据区：部署数据库、缓存、存储。
- 管理区：运维、监控、堡垒机、日志平台。

答题要点：外部请求不应直接访问数据库；不同安全等级区域之间通过防火墙、网关或访问控制隔离。

### DMZ

DMZ 用于隔离外网和内网。

常见设计：

- 外部用户先访问负载均衡或反向代理。
- 对外服务部署在 DMZ。
- DMZ 只能访问必要的内部服务接口。
- 数据库放在内网数据区，不直接暴露。

易错点：把数据库、核心业务系统直接放到公网或 DMZ，是安全风险。

### 专线、VPN 和公网 HTTPS

| 方式 | 适合场景 | 特点 |
| --- | --- | --- |
| 专线 | 稳定、大流量、企业间核心系统互联 | 质量稳定，成本高 |
| VPN | 跨地域安全接入、分支机构互联 | 基于公网加密，成本适中 |
| 公网 HTTPS | 开放 API、互联网用户访问 | 易接入，但需认证、限流、防攻击 |

选择时看安全等级、成本、带宽、稳定性和接入对象。

### 协议选择

| 协议 | 适合场景 |
| --- | --- |
| HTTP/REST | 通用业务接口、开放平台 |
| HTTPS | 需要传输加密的 Web 和接口访问 |
| TCP | 长连接、可靠传输、协议自定义 |
| UDP | 低延迟、可容忍少量丢包的音视频或实时数据 |
| WebSocket | 浏览器双向实时通信 |
| MQTT | 物联网设备、弱网、小报文发布订阅 |

易错点：实时不等于必须 UDP。金融交易、订单状态这类实时查询仍然需要可靠性。

### 网络高可用

常见措施：

- 双链路或多运营商接入。
- 负载均衡设备主备或集群。
- 防火墙、交换机、路由器冗余。
- DNS 或全局流量调度实现跨地域切换。
- 健康检查自动摘除故障节点。

答题时要补充故障检测和切换机制，只写“双机部署”不够。

### 网络性能优化

常见措施：

- 静态资源使用 CDN。
- 就近接入或边缘节点降低延迟。
- 大文件分片上传、断点续传。
- 压缩、缓存、连接复用。
- 对关键业务流量设置 QoS。
- 对内部调用减少跨地域链路。

### 网络安全

常见措施：

- 边界防护：防火墙、WAF、DDoS 防护。
- 访问控制：安全组、ACL、最小开放端口。
- 传输加密：HTTPS、VPN、证书。
- 运维安全：堡垒机、双因素认证、操作审计。
- 入侵检测：IDS/IPS、日志监控、异常告警。

### 通信与网络架构答题模板

```text
将系统划分为外网、DMZ、应用区、数据区和管理区；外部流量通过 DNS、负载均衡、WAF 和 API 网关进入 DMZ，再访问内网应用服务，数据库只在数据区开放必要端口；跨机构通信根据安全和稳定性选择专线、VPN 或 HTTPS；通过双链路、设备冗余、健康检查和流量切换保证可用性；通过 CDN、缓存、压缩和就近接入优化性能。
```
