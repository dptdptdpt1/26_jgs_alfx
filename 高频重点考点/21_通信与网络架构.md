# 通信与网络架构

## 考试中一般怎么考

1. 网络拓扑：要求设计内外网、DMZ、负载均衡、防火墙、专线或 VPN。
2. 通信协议：问 HTTP、HTTPS、TCP、UDP、MQTT、WebSocket 等如何选择。
3. 网络安全：问边界防护、访问控制、传输加密、入侵检测。
4. 高可用网络：问链路冗余、设备冗余、故障切换和流量调度。
5. 性能优化：问带宽、延迟、QoS、CDN、边缘节点如何处理。
6. 云网络：问 VPC、子网、路由表、安全组、NAT、负载均衡如何配合。

## 针对考法梳理知识点

### 网络分区

常见分区：

- 外网区：用户或外部系统访问入口。
- DMZ 区：放置 Web、网关、反向代理等对外服务。
- 应用区：部署业务服务。
- 数据区：部署数据库、缓存、存储。
- 管理区：运维、监控、堡垒机、日志平台。

答题要点：外部请求不应直接访问数据库；不同安全等级区域之间通过防火墙、网关或访问控制隔离。

### OSI 和 TCP/IP 分层

考试一般不要求深入协议细节，但要知道分层定位。

| 层次 | 关注 |
| --- | --- |
| 应用层 | HTTP、HTTPS、DNS、MQTT、WebSocket |
| 传输层 | TCP、UDP，负责端到端传输 |
| 网络层 | IP、路由、子网、跨网段转发 |
| 链路层 | 以太网、交换、MAC |

排查问题时也可按层定位：DNS 解析、网络连通、端口、TLS、应用响应。

### DMZ

DMZ 用于隔离外网和内网。

常见设计：

- 外部用户先访问负载均衡或反向代理。
- 对外服务部署在 DMZ。
- DMZ 只能访问必要的内部服务接口。
- 数据库放在内网数据区，不直接暴露。

易错点：把数据库、核心业务系统直接放到公网或 DMZ，是安全风险。

### 专线、VPN 和公网 HTTPS

| 方式 | 适合场景 | 特点 |
| --- | --- | --- |
| 专线 | 稳定、大流量、企业间核心系统互联 | 质量稳定，成本高 |
| VPN | 跨地域安全接入、分支机构互联 | 基于公网加密，成本适中 |
| 公网 HTTPS | 开放 API、互联网用户访问 | 易接入，但需认证、限流、防攻击 |

选择时看安全等级、成本、带宽、稳定性和接入对象。

### 云网络常见组件

| 组件 | 作用 |
| --- | --- |
| VPC | 云上私有网络边界 |
| 子网 | 在 VPC 内划分不同网段和可用区资源 |
| 路由表 | 控制流量下一跳 |
| 安全组 | 实例级访问控制 |
| ACL | 子网级访问控制 |
| NAT 网关 | 内网资源访问公网，但不直接暴露入站 |
| 弹性公网 IP | 为资源提供公网访问地址 |
| 负载均衡 | 分发流量并做健康检查 |

云上设计要避免数据库直接暴露公网。应用实例通常放私有子网，通过负载均衡、NAT 和安全组控制访问。

### 协议选择

| 协议 | 适合场景 |
| --- | --- |
| HTTP/REST | 通用业务接口、开放平台 |
| HTTPS | 需要传输加密的 Web 和接口访问 |
| TCP | 长连接、可靠传输、协议自定义 |
| UDP | 低延迟、可容忍少量丢包的音视频或实时数据 |
| WebSocket | 浏览器双向实时通信 |
| MQTT | 物联网设备、弱网、小报文发布订阅 |

易错点：实时不等于必须 UDP。金融交易、订单状态这类实时查询仍然需要可靠性。

### TCP 和 UDP

| 对比 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 保证顺序、重传、拥塞控制 | 不保证可靠和顺序 |
| 开销 | 较高 | 较低 |
| 适用 | 交易、文件、接口调用、可靠消息 | 音视频、游戏、实时采集、可容忍丢包场景 |

如果业务必须保证数据完整和顺序，优先 TCP。若更关注低延迟且可容忍少量丢包，可考虑 UDP 并在应用层补必要控制。

### HTTP、HTTP/2 和 WebSocket

| 协议 | 特点 | 适用 |
| --- | --- | --- |
| HTTP/1.1 | 通用请求响应，支持长连接 | 普通 Web 和 REST 接口 |
| HTTP/2 | 多路复用、头部压缩 | 高并发 Web/API 请求 |
| WebSocket | 建立长连接，支持双向通信 | 实时聊天、实时通知、监控大屏 |

WebSocket 适合服务端主动推送。普通查询和交易接口不需要为了“实时”强行使用 WebSocket。

### DNS、负载均衡和反向代理

典型入口链路：

```text
用户 -> DNS -> CDN / GSLB -> 负载均衡 -> 反向代理 / 网关 -> 应用服务
```

| 组件 | 作用 |
| --- | --- |
| DNS | 域名解析到入口地址 |
| GSLB | 全局流量调度，按地域、健康状态分配流量 |
| 负载均衡 | 将请求分发到多个后端实例 |
| 反向代理 | 转发请求、TLS 卸载、缓存、压缩 |
| API 网关 | 认证、鉴权、路由、限流、审计 |

入口高可用要配合健康检查、故障摘除和跨地域切换。

### 网络高可用

常见措施：

- 双链路或多运营商接入。
- 负载均衡设备主备或集群。
- 防火墙、交换机、路由器冗余。
- DNS 或全局流量调度实现跨地域切换。
- 健康检查自动摘除故障节点。

答题时要补充故障检测和切换机制，只写“双机部署”不够。

### 多地域和多活网络

多地域部署常用 DNS/GSLB 做全局流量调度。

常见方式：

- 同城双中心：低延迟，适合同城容灾。
- 两地三中心：兼顾同城高可用和异地容灾。
- 异地多活：多地域同时服务，复杂度最高。

多活网络要考虑跨地域延迟、数据一致性、流量切换、故障探测和回切策略。

### 网络性能优化

常见措施：

- 静态资源使用 CDN。
- 就近接入或边缘节点降低延迟。
- 大文件分片上传、断点续传。
- 压缩、缓存、连接复用。
- 对关键业务流量设置 QoS。
- 对内部调用减少跨地域链路。

### 网络安全

常见措施：

- 边界防护：防火墙、WAF、DDoS 防护。
- 访问控制：安全组、ACL、最小开放端口。
- 传输加密：HTTPS、VPN、证书。
- 运维安全：堡垒机、双因素认证、操作审计。
- 入侵检测：IDS/IPS、日志监控、异常告警。

### 安全设备和机制区别

| 机制 | 作用 |
| --- | --- |
| 防火墙 | 基于网络层和传输层控制访问 |
| WAF | 保护 Web 应用，防 SQL 注入、XSS 等 |
| IDS | 入侵检测，发现异常并告警 |
| IPS | 入侵防御，发现异常并阻断 |
| DDoS 防护 | 抵御大流量攻击 |
| 堡垒机 | 运维登录管控和操作审计 |

零信任强调不默认信任内网访问，要持续认证、最小权限和动态授权。

### 南北向和东西向流量

| 流量 | 含义 | 治理 |
| --- | --- | --- |
| 南北向 | 外部用户和数据中心之间的流量 | WAF、网关、负载均衡、防火墙 |
| 东西向 | 数据中心或集群内部服务间流量 | 服务网格、网络策略、微隔离、链路追踪 |

微服务增多后，东西向流量占比上升，需要服务间认证、限流、熔断和可观测。

### 网络故障排查

常见排查维度：

- DNS 是否解析正确。
- 路由和安全组是否放通。
- 端口是否监听。
- TLS 证书是否有效。
- 网络延迟、丢包和带宽是否异常。
- 连接数、线程池和负载均衡健康检查是否正常。

### 通信与网络架构答题模板

```text
将系统划分为外网、DMZ、应用区、数据区和管理区；外部流量通过 DNS、负载均衡、WAF 和 API 网关进入 DMZ，再访问内网应用服务，数据库只在数据区开放必要端口；跨机构通信根据安全和稳定性选择专线、VPN 或 HTTPS；通过双链路、设备冗余、健康检查和流量切换保证可用性；通过 CDN、缓存、压缩和就近接入优化性能。
```
