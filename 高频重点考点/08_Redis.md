# Redis

> 重要程度：P0  
> 考纲定位：缓存、性能优化、高可用和分布式系统案例的常用组件。

## 优先掌握

1. Redis 作为缓存、计数器、排行榜、会话和分布式锁的场景。
2. 缓存穿透、击穿、雪崩和一致性处理。
3. 高可用：主从、哨兵、集群。
4. 热 Key、大 Key、过期策略和持久化边界。

## 概念和场景

| 重要度 | 内容 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | 缓存 | 把热点数据放在内存中减少数据库访问 | 商品详情页先查 Redis，未命中再查 MySQL |
| P0 | 缓存穿透 | 查询不存在的数据绕过缓存打到数据库 | 恶意请求不存在商品 id，需缓存空值或布隆过滤器 |
| P0 | 缓存击穿 | 单个热点 Key 失效后大量请求打到数据库 | 爆款商品缓存过期，需互斥重建或逻辑过期 |
| P0 | 缓存雪崩 | 大量 Key 同时失效或缓存集群故障 | 批量缓存同一时间过期，需随机过期和多级保护 |
| P0 | 缓存一致性 | 缓存与数据库数据要在可接受时间内一致 | 更新商品价格后删除缓存，由下次查询重建 |
| P1 | 分布式锁 | 多节点协调互斥访问 | 防止多个实例同时生成同一张发票 |
| P1 | 持久化 | 将内存数据保存到磁盘 | Redis 重启后可恢复部分数据，但不能替代数据库 |
| P1 | 主从/哨兵/集群 | 提供读扩展、高可用和分片 | 缓存节点故障后自动切换，集群分担大容量 Key |

## 缓存一致性答题顺序

1. 数据库作为最终权威数据源。
2. 更新数据时优先更新数据库，再删除缓存。
3. 删除失败要有重试、消息补偿或定时校验。
4. 对强一致场景，关键读可以短时间读库或加版本校验。
5. 对最终一致场景，说明允许的延迟窗口。

## 常见场景处理

| 场景 | 处理 |
| --- | --- |
| 热点 Key | 本地缓存、多副本、拆分 Key、限流。 |
| 大 Key | 拆分结构、异步删除、避免一次取大量数据。 |
| 秒杀扣库存 | Redis 预扣减、Lua 保证原子性、异步落库、失败补偿。 |
| 缓存服务故障 | 降级、限流、熔断、保护数据库。 |

## 易混点

| 易混项 | 区分 |
| --- | --- |
| Redis 缓存 vs 数据库 | Redis 追求速度和临时状态；数据库保存权威持久数据。 |
| 击穿 vs 雪崩 | 击穿是热点 Key 失效；雪崩是大量 Key 或缓存整体失效。 |
| 分布式锁 vs 事务 | 分布式锁控制并发入口；事务保证数据库内部一致性。 |
