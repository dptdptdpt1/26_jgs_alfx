# 架构演化与遗留系统改造

## 考试中一般怎么考

1. 遗留系统改造：问旧系统如何逐步拆分、替换、集成或保留。
2. 单体到微服务：要求说明拆分顺序、数据迁移、接口兼容和风险控制。
3. 数据迁移：问如何保证迁移准确性、一致性和可回滚。
4. 灰度演进：问如何降低切换风险，支持新旧系统并行。
5. 技术债治理：问如何评估风险、制定演进路线和控制改造范围。

## 针对考法梳理知识点

### 架构演化原则

常见原则：

- 业务连续优先，不能为了改造中断核心业务。
- 先外围后核心，先低风险后高风险。
- 保持接口兼容，减少对调用方影响。
- 数据迁移可校验、可回滚。
- 每一步都有监控、灰度和回退方案。

### 遗留系统处理策略

| 策略 | 适合场景 |
| --- | --- |
| 封装 | 旧系统稳定但接口落后，通过适配层对外提供标准接口 |
| 替换 | 旧系统无法维护或风险过高，逐步用新系统替代 |
| 扩展 | 核心暂不动，在外围增加新能力 |
| 重构 | 功能仍有价值，但内部结构混乱 |
| 退役 | 业务已停止或被新系统覆盖 |

易错点：不要一上来就“全部重写”。核心系统通常要渐进改造。

### 单体到微服务

常见步骤：

1. 梳理业务域和模块依赖。
2. 选择边界清晰、风险较低的模块先拆。
3. 为旧系统增加 API 或防腐层。
4. 新服务独立部署，并接入注册、配置、监控、日志。
5. 逐步迁移流量和数据。
6. 验证稳定后再拆核心模块。

拆分时要同时考虑数据归属。只拆代码不拆数据，服务之间仍可能强耦合。

### 防腐层

防腐层用于隔离新旧系统模型和接口。

作用：

- 把旧系统接口转换为新系统需要的模型。
- 屏蔽旧系统字段、协议、异常格式。
- 避免新系统直接依赖旧系统内部结构。

适合新旧系统长期并行或逐步迁移的场景。

### 数据迁移

常见做法：

- 迁移前清洗、去重、补全和字段映射。
- 先全量迁移，再增量同步。
- 迁移后做行数、金额、状态、抽样和业务对账。
- 切换前冻结写入或使用双写/日志同步。
- 保留回滚方案和旧数据备份。

易错点：只写“导入数据”不够。案例题通常要写校验、对账、增量同步和回滚。

### 双写和数据一致性

双写常用于新旧系统并行期，但风险高。

常见风险：

- 一个系统写成功，另一个失败。
- 写入顺序不同导致状态不一致。
- 回滚和补偿复杂。

常见控制：

- 以一个系统为主数据源。
- 通过消息、日志或 CDC 同步到另一个系统。
- 建立对账和补偿任务。
- 缩短双写窗口，避免长期并行。

### 灰度迁移

常见灰度方式：

- 按用户、机构、地区、业务类型切流。
- 小比例流量先进入新系统。
- 监控错误率、延迟、业务指标。
- 出现异常快速切回旧系统。

灰度迁移适合降低切换风险，但要求新旧系统接口和数据兼容。

### 架构演化答题模板

```text
先评估旧系统的业务价值、技术风险和依赖关系；对稳定但难改的能力用接口封装和防腐层隔离；选择边界清晰、风险较低的模块先拆分；通过全量迁移加增量同步完成数据迁移，并做校验、对账和备份；采用灰度切流监控业务指标，异常时快速回滚；最终逐步下线被替代的旧模块。
```
