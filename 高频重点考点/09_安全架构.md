# 安全架构

## 考试中一般怎么考

1. 风险识别：要求指出身份、权限、数据、接口、日志方面的风险。
2. 认证授权：问如何确认用户身份、如何控制用户能访问什么。
3. 接口安全：问签名、时间戳、Nonce、防重放、限流的机制。
4. 数据保护：问传输加密、存储加密、脱敏、密钥管理。
5. 审计追踪：问关键操作为什么要记录日志。
6. 安全体系：问 WPDRRC、安全域、脆弱性分析和整体防护框架。

## 针对考法梳理知识点

### 认证和授权不是一回事

认证解决“你是谁”，例如用户名密码、短信验证码、Token、证书、多因素认证。

授权解决“你能做什么”，例如 RBAC、ABAC、接口权限、菜单权限、数据权限。

考试里如果系统只做登录认证，但没有权限控制，仍然存在越权风险。

### RBAC 的基本机制

RBAC 是基于角色的访问控制。用户不直接绑定权限，而是绑定角色，角色再绑定权限。

基本关系是：

```text
用户 -> 角色 -> 权限
```

好处是权限管理更集中，适合企业系统、后台管理系统。

常见风险是角色过大、权限分配过宽，需要最小权限原则。

### ABAC

ABAC 是基于属性的访问控制。它根据用户属性、资源属性、环境属性和操作属性综合判断是否允许访问。

例子：只有“华东区销售经理”可以在“工作时间”查看“华东区客户”的“报价信息”。

ABAC 比 RBAC 更灵活，适合权限规则复杂、需要细粒度控制的系统。代价是策略设计和解释成本更高。

### OAuth2 和单点登录

OAuth2 常用于第三方授权。用户不直接把密码交给第三方应用，而是由授权服务器颁发访问令牌，第三方应用拿令牌访问受保护资源。

单点登录解决的是多个系统重复登录的问题。用户在统一身份认证中心登录一次，访问其他系统时通过票据或 Token 完成身份确认。

答题时注意：OAuth2 重点是授权，SSO 重点是统一登录体验和统一身份认证。

### 接口签名机制

接口签名用于防止请求参数被篡改。

常见流程：

1. 客户端按约定把参数、时间戳、随机数等拼接。
2. 使用密钥计算签名。
3. 服务端用同样规则重新计算签名。
4. 两个签名一致，说明参数未被篡改。

签名解决篡改问题，但不单独解决重放问题。

### 防重放机制

重放攻击是攻击者截获一次合法请求后，重复发送这次请求。

常见处理：

- 时间戳：请求超过有效时间窗口就拒绝。
- Nonce：每次请求使用唯一随机数，服务端记录已使用值。
- 请求序列号：同一调用方请求序号递增。

防重放通常和签名一起使用。签名保证内容未改，时间戳和 Nonce 保证请求不能被重复使用。

### 加密、签名、摘要

| 目标 | 技术 |
| --- | --- |
| 机密性 | 对称加密（AES，速度快，适合大量数据） / 非对称加密（RSA/ECC，适合密钥交换和签名） |
| 完整性 | 消息摘要 / Hash（SHA-256） / MAC |
| 身份认证 | 数字证书 / 数字签名 |
| 不可抵赖 | 数字签名（私钥签名，公钥验签） |
| 密钥交换 | 非对称加密 / TLS 握手 |

常见组合：用 AES 加密业务数据，用 RSA 加密 AES 密钥，用 SHA-256 生成摘要并通过数字签名保证完整性和不可抵赖性。

### 数据保护

**密码类数据**：不能明文保存，采用加盐 Hash 存储（bcrypt/PBKDF2/Argon2 等慢哈希算法）。

**敏感字段**（身份证、手机号、银行卡）：数据库字段加密存储，页面脱敏展示（如 138****8888），日志中禁止输出明文。

**传输加密**：HTTPS/TLS 防窃听。

**密钥管理**：避免写死在代码中，应支持密钥轮换、权限控制和安全存储（KMS）。

### JWT

JWT（JSON Web Token）是常用的无状态 Token 方案，适合前后端分离和移动端。

结构：Header（算法）+ Payload（用户信息和过期时间）+ Signature（签名防篡改）。

优点：无状态，服务端不需要存储 Session。缺点：Token 签发后无法主动吊销，需配合短过期时间 + 刷新机制。

### OAuth2 和单点登录

OAuth2 常用于第三方授权。用户不直接把密码交给第三方应用，而是由授权服务器颁发访问令牌，第三方应用拿令牌访问受保护资源。

单点登录（SSO）解决多个系统重复登录的问题。用户在统一身份认证中心登录一次，访问其他系统时通过票据或 Token 完成身份确认。

答题时注意：OAuth2 重点是授权，SSO 重点是统一登录体验和统一身份认证。

### 审计日志

审计日志用于事后追踪。关键操作应该记录谁、在什么时间、从哪里、做了什么、结果如何。

常见审计对象：

- 登录和退出。
- 权限变更。
- 重要数据增删改。
- 资金、订单、审批类操作。
- 安全异常。

### 常见攻击防护

| 攻击 | 原理 | 防护 |
| --- | --- | --- |
| SQL 注入 | 把恶意 SQL 拼进输入参数，改变原查询语义 | 参数化查询、预编译、输入校验、最小数据库权限 |
| XSS | 注入脚本在用户浏览器执行 | 输出编码、输入过滤、内容安全策略、Cookie 设置 HttpOnly |
| CSRF | 借用户已登录状态伪造请求 | CSRF Token、SameSite Cookie、关键操作二次确认 |
| 重放攻击 | 重复发送截获的合法请求 | 时间戳、Nonce、签名、请求序列号 |
| 暴力破解 | 反复尝试密码或验证码 | 登录限流、验证码、账号锁定、多因素认证 |
| 文件上传漏洞 | 上传恶意脚本获取服务器权限 | 文件类型白名单校验、大小限制、重命名存储、独立存储域 |
| 越权访问 | 水平越权访问他人数据，垂直越权获取更高权限 | 后端接口强制权限校验、RBAC + 数据权限、不能只靠前端控制 |

### VPN、HTTPS/TLS 的区别

HTTPS/TLS 保护应用层通信，常用于浏览器和服务端、服务间接口加密。

VPN 在网络层或链路层建立安全通道，常用于远程办公、跨机房或专网访问。

考试中如果是公网接口传输敏感数据，优先写 HTTPS/TLS；如果是让外部人员安全接入内网系统，可以写 VPN。

### WPDRRC 模型

WPDRRC 用于描述信息安全保障的动态过程。

| 环节 | 含义 | 常见措施 |
| --- | --- | --- |
| 预警 | 提前发现威胁趋势 | 威胁情报、漏洞公告、态势感知 |
| 保护 | 降低被攻击概率 | 防火墙、WAF、加固、访问控制 |
| 检测 | 发现异常和入侵 | IDS/IPS、日志分析、漏洞扫描 |
| 响应 | 事件发生后处置 | 应急预案、隔离、封禁、通报 |
| 恢复 | 恢复业务和数据 | 备份恢复、容灾切换、补丁修复 |
| 反击 | 溯源取证和反制 | 审计取证、攻击源追踪、证据保全 |

三大要素是人员、策略和技术。考试问安全体系时，可以用 WPDRRC 按事前、事中、事后组织答案。

### 安全体系规划

安全体系不要只堆安全产品。可以按保护对象分层：

- 物理安全：机房、门禁、供电、防火、防水。
- 网络安全：安全域、DMZ、防火墙、VPN、入侵检测。
- 主机安全：操作系统加固、补丁、账号、病毒防护。
- 应用安全：认证授权、输入校验、防注入、防重放。
- 数据安全：分级分类、加密、脱敏、备份、审计。
- 管理安全：制度、岗位、培训、应急预案、权限审批。

答题顺序：先识别资产和边界，再分析威胁和脆弱性，最后从技术、管理、人员三个方面给控制措施。

### 脆弱性分析

脆弱性是系统容易被利用的薄弱点，不等同于已经发生的攻击。

常见脆弱性：

- 默认口令、弱口令、账号共享。
- 未打补丁、组件版本过旧。
- 端口暴露过多，安全域隔离不足。
- 接口缺少鉴权、签名、限流。
- 敏感数据明文存储或日志明文输出。
- 缺少备份、恢复演练和应急流程。

答题时可按“资产 -> 威胁 -> 脆弱性 -> 风险 -> 控制措施”展开。

### 权限控制怎么落地

权限题不要只写 RBAC，要说明权限控制点。

常见层次：

- 菜单权限：用户能看到哪些菜单和页面。
- 按钮权限：用户能执行新增、删除、审批、导出等哪些操作。
- 接口权限：后端接口必须校验权限，不能只靠前端隐藏按钮。
- 数据权限：只能访问本人、本部门、本区域或授权范围内的数据。
- 字段权限：敏感字段是否可见、是否脱敏。

易错点：只在前端控制菜单或按钮不安全。攻击者可以绕过前端直接调用接口，所以后端必须做认证和授权校验。

### 敏感数据分级保护

不同敏感级别的数据保护强度不同。

| 数据类型 | 风险 | 保护措施 |
| --- | --- | --- |
| 口令 | 泄露后可直接登录 | 加盐哈希存储，不明文保存 |
| 身份证、手机号 | 隐私泄露 | 加密存储、展示脱敏、访问审计 |
| 支付信息 | 资金风险 | 强认证、最小权限、加密、风控 |
| 日志中的敏感字段 | 二次泄露 | 日志脱敏、权限控制、保留周期 |
| 备份数据 | 离线泄露 | 备份加密、访问控制、定期恢复演练 |

考试问“如何保护用户隐私”，可以从采集最小化、传输加密、存储加密、展示脱敏、访问控制、审计日志、备份保护这些角度答。

### 认证机制比较

| 方式 | 优点 | 风险或限制 |
| --- | --- | --- |
| 用户名口令 | 实现简单 | 弱口令、撞库、泄露风险 |
| 短信验证码 | 用户体验较好 | SIM 卡风险、短信劫持、成本 |
| 多因素认证 | 安全性更高 | 使用复杂度增加 |
| 数字证书 | 身份可信度高 | 证书管理和部署成本 |
| Token | 适合前后端分离和移动端 | 令牌泄露后需过期、刷新、吊销机制 |

关键系统常采用多因素认证，例如口令加短信、口令加动态令牌。

### 接口安全答题模板

公网接口安全可以按固定层次写：

1. 身份认证：确认调用方身份，例如 Token、证书、AppKey。
2. 权限控制：校验调用方是否有访问该接口和数据的权限。
3. 传输加密：使用 HTTPS/TLS 防窃听。
4. 参数签名：防止请求参数被篡改。
5. 时间戳和 Nonce：防止重放。
6. 限流和黑名单：防止刷接口和暴力攻击。
7. 日志审计：记录调用方、时间、参数摘要、结果和异常。

### 安全题常见失分点

- 只写“登录验证”，没有写授权和数据权限。
- 只写“加密”，没有区分传输加密和存储加密。
- 只写”签名”，没有写时间戳和 Nonce，不能防重放。
- 只写”前端隐藏按钮”，没有写后端接口鉴权。
- 审计日志记录敏感明文，反而造成数据泄露。

### 网络与边界安全

架构图填空题中常出现安全组件的位置划分：

```
用户
  ↓
CDN / WAF
  ↓
负载均衡
  ↓
DMZ 区：Web 服务器、反向代理
  ↓（防火墙）
应用区：业务服务、API 网关
  ↓
数据区：数据库、缓存、文件服务器
```

考点：

- 数据库不能直接暴露公网，只允许应用服务器通过受控端口访问。
- Web 服务器可放 DMZ，应用服务器和数据库放内网。
- 外部访问通过防火墙、WAF、网关控制。
- 管理运维通过 VPN / 堡垒机接入。

关键组件：

| 组件 | 作用 |
| --- | --- |
| 防火墙 | 网络层访问控制，隔离安全域 |
| WAF | Web 应用防火墙，防护 SQL 注入、XSS 等 |
| DMZ | 隔离区，放置对外服务，保护内网 |
| VPN | 远程安全接入内网 |
| IDS/IPS | 入侵检测/防御系统 |
| 堡垒机 | 运维审计和权限管控，统一运维入口 |
| 网闸 | 物理隔离，用于涉密网络 |

### 安全运维与主机安全

- 操作系统安全基线加固，关闭不必要服务和端口。
- 定期安装安全补丁。
- 禁止弱口令和默认账号。
- 配置主机防火墙。
- 部署主机入侵检测。
- 账号权限最小化。
- 定期漏洞扫描和安全基线检查。

### 微服务与接口安全

微服务架构下的安全重点：

- API 网关统一鉴权、限流、日志审计、黑白名单。
- OAuth2 / JWT 接口认证。
- 服务间调用使用 mTLS（双向 TLS）。
- 服务注册发现权限控制。
- 第三方接口调用采用 AppKey + AppSecret + 时间戳 + 随机数 + 签名。

### 等级保护

政务、金融、医疗等系统需要按等级保护要求建设。核心要求：

身份鉴别、访问控制、安全审计、入侵防范、数据完整性、数据保密性、备份恢复、安全管理制度。

答题模板：

> 系统应按照网络安全等级保护要求进行建设，从物理安全、网络安全、主机安全、应用安全、数据安全和安全管理等方面设计安全防护措施。

### 安全架构设计答题模板

案例题问”该系统应采取哪些安全措施”时，按以下结构答：

1. **网络安全**：部署防火墙、WAF、IDS，划分 DMZ 区、应用区和数据区。
2. **身份认证与权限控制**：统一身份认证、强密码策略、多因素认证、RBAC 权限模型，后端接口强制校验。
3. **数据安全**：敏感数据加密存储，传输使用 HTTPS，密码加盐 Hash，脱敏展示。
4. **接口安全**：API 网关鉴权、限流、签名校验、防重放、日志记录。
5. **日志审计**：记录关键操作日志，集中存储，防篡改。
6. **运维安全**：堡垒机、VPN、定期漏洞扫描和补丁更新。
7. **备份容灾**：定期备份、异地备份、灾备演练，满足 RPO/RTO。

### 高频简答句

**防止数据泄露**：对敏感数据分级分类管理，传输 HTTPS 加密，存储字段级加密，展示脱敏，访问权限控制和审计记录。

**防止接口被恶意调用**：身份认证、Token 鉴权、时间戳、随机数、数字签名、访问频率限制，防伪造、重放和恶意刷接口。

**防止越权访问**：后端接口统一权限校验，RBAC 模型，最小权限原则，不依赖前端控制。

**防止数据库暴露**：数据库部署内网数据区，不暴露公网，只允许应用服务器受控访问，数据库账号最小权限。
