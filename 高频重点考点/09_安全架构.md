# 安全架构

## 考试中一般怎么考

1. 风险识别：要求指出身份、权限、数据、接口、日志方面的风险。
2. 认证授权：问如何确认用户身份、如何控制用户能访问什么。
3. 接口安全：问签名、时间戳、Nonce、防重放、限流的机制。
4. 数据保护：问传输加密、存储加密、脱敏、密钥管理。
5. 审计追踪：问关键操作为什么要记录日志。

## 针对考法梳理知识点

### 认证和授权不是一回事

认证解决“你是谁”，例如用户名密码、短信验证码、Token、证书、多因素认证。

授权解决“你能做什么”，例如 RBAC、ABAC、接口权限、菜单权限、数据权限。

考试里如果系统只做登录认证，但没有权限控制，仍然存在越权风险。

### RBAC 的基本机制

RBAC 是基于角色的访问控制。用户不直接绑定权限，而是绑定角色，角色再绑定权限。

基本关系是：

```text
用户 -> 角色 -> 权限
```

好处是权限管理更集中，适合企业系统、后台管理系统。

常见风险是角色过大、权限分配过宽，需要最小权限原则。

### 接口签名机制

接口签名用于防止请求参数被篡改。

常见流程：

1. 客户端按约定把参数、时间戳、随机数等拼接。
2. 使用密钥计算签名。
3. 服务端用同样规则重新计算签名。
4. 两个签名一致，说明参数未被篡改。

签名解决篡改问题，但不单独解决重放问题。

### 防重放机制

重放攻击是攻击者截获一次合法请求后，重复发送这次请求。

常见处理：

- 时间戳：请求超过有效时间窗口就拒绝。
- Nonce：每次请求使用唯一随机数，服务端记录已使用值。
- 请求序列号：同一调用方请求序号递增。

防重放通常和签名一起使用。签名保证内容未改，时间戳和 Nonce 保证请求不能被重复使用。

### 数据保护

传输加密保护数据在网络传输过程中不被窃听，常用 HTTPS/TLS。

存储加密保护数据库、文件、备份中的敏感数据。

脱敏用于展示和日志场景，例如手机号只显示中间几位星号。

密钥管理要避免把密钥写死在代码中，应支持密钥轮换、权限控制和安全存储。

### 审计日志

审计日志用于事后追踪。关键操作应该记录谁、在什么时间、从哪里、做了什么、结果如何。

常见审计对象：

- 登录和退出。
- 权限变更。
- 重要数据增删改。
- 资金、订单、审批类操作。
- 安全异常。
