# 安全架构

## 考试中一般怎么考

1. 风险识别：要求指出身份、权限、数据、接口、日志方面的风险。
2. 认证授权：问如何确认用户身份、如何控制用户能访问什么。
3. 接口安全：问签名、时间戳、Nonce、防重放、限流的机制。
4. 数据保护：问传输加密、存储加密、脱敏、密钥管理。
5. 审计追踪：问关键操作为什么要记录日志。

## 针对考法梳理知识点

### 认证和授权不是一回事

认证解决“你是谁”，例如用户名密码、短信验证码、Token、证书、多因素认证。

授权解决“你能做什么”，例如 RBAC、ABAC、接口权限、菜单权限、数据权限。

考试里如果系统只做登录认证，但没有权限控制，仍然存在越权风险。

### RBAC 的基本机制

RBAC 是基于角色的访问控制。用户不直接绑定权限，而是绑定角色，角色再绑定权限。

基本关系是：

```text
用户 -> 角色 -> 权限
```

好处是权限管理更集中，适合企业系统、后台管理系统。

常见风险是角色过大、权限分配过宽，需要最小权限原则。

### ABAC

ABAC 是基于属性的访问控制。它根据用户属性、资源属性、环境属性和操作属性综合判断是否允许访问。

例子：只有“华东区销售经理”可以在“工作时间”查看“华东区客户”的“报价信息”。

ABAC 比 RBAC 更灵活，适合权限规则复杂、需要细粒度控制的系统。代价是策略设计和解释成本更高。

### OAuth2 和单点登录

OAuth2 常用于第三方授权。用户不直接把密码交给第三方应用，而是由授权服务器颁发访问令牌，第三方应用拿令牌访问受保护资源。

单点登录解决的是多个系统重复登录的问题。用户在统一身份认证中心登录一次，访问其他系统时通过票据或 Token 完成身份确认。

答题时注意：OAuth2 重点是授权，SSO 重点是统一登录体验和统一身份认证。

### 接口签名机制

接口签名用于防止请求参数被篡改。

常见流程：

1. 客户端按约定把参数、时间戳、随机数等拼接。
2. 使用密钥计算签名。
3. 服务端用同样规则重新计算签名。
4. 两个签名一致，说明参数未被篡改。

签名解决篡改问题，但不单独解决重放问题。

### 防重放机制

重放攻击是攻击者截获一次合法请求后，重复发送这次请求。

常见处理：

- 时间戳：请求超过有效时间窗口就拒绝。
- Nonce：每次请求使用唯一随机数，服务端记录已使用值。
- 请求序列号：同一调用方请求序号递增。

防重放通常和签名一起使用。签名保证内容未改，时间戳和 Nonce 保证请求不能被重复使用。

### 数据保护

传输加密保护数据在网络传输过程中不被窃听，常用 HTTPS/TLS。

存储加密保护数据库、文件、备份中的敏感数据。

脱敏用于展示和日志场景，例如手机号只显示中间几位星号。

密钥管理要避免把密钥写死在代码中，应支持密钥轮换、权限控制和安全存储。

### 审计日志

审计日志用于事后追踪。关键操作应该记录谁、在什么时间、从哪里、做了什么、结果如何。

常见审计对象：

- 登录和退出。
- 权限变更。
- 重要数据增删改。
- 资金、订单、审批类操作。
- 安全异常。

### 常见攻击防护

| 攻击 | 原理 | 防护 |
| --- | --- | --- |
| SQL 注入 | 把恶意 SQL 拼进输入参数，改变原查询语义 | 参数化查询、预编译、输入校验、最小数据库权限 |
| XSS | 注入脚本在用户浏览器执行 | 输出编码、输入过滤、内容安全策略、Cookie 设置 HttpOnly |
| CSRF | 借用户已登录状态伪造请求 | CSRF Token、SameSite Cookie、关键操作二次确认 |
| 重放攻击 | 重复发送截获的合法请求 | 时间戳、Nonce、签名、请求序列号 |
| 暴力破解 | 反复尝试密码或验证码 | 登录限流、验证码、账号锁定、多因素认证 |

### VPN、HTTPS/TLS 的区别

HTTPS/TLS 保护应用层通信，常用于浏览器和服务端、服务间接口加密。

VPN 在网络层或链路层建立安全通道，常用于远程办公、跨机房或专网访问。

考试中如果是公网接口传输敏感数据，优先写 HTTPS/TLS；如果是让外部人员安全接入内网系统，可以写 VPN。

### 权限控制怎么落地

权限题不要只写 RBAC，要说明权限控制点。

常见层次：

- 菜单权限：用户能看到哪些菜单和页面。
- 按钮权限：用户能执行新增、删除、审批、导出等哪些操作。
- 接口权限：后端接口必须校验权限，不能只靠前端隐藏按钮。
- 数据权限：只能访问本人、本部门、本区域或授权范围内的数据。
- 字段权限：敏感字段是否可见、是否脱敏。

易错点：只在前端控制菜单或按钮不安全。攻击者可以绕过前端直接调用接口，所以后端必须做认证和授权校验。

### 敏感数据分级保护

不同敏感级别的数据保护强度不同。

| 数据类型 | 风险 | 保护措施 |
| --- | --- | --- |
| 口令 | 泄露后可直接登录 | 加盐哈希存储，不明文保存 |
| 身份证、手机号 | 隐私泄露 | 加密存储、展示脱敏、访问审计 |
| 支付信息 | 资金风险 | 强认证、最小权限、加密、风控 |
| 日志中的敏感字段 | 二次泄露 | 日志脱敏、权限控制、保留周期 |
| 备份数据 | 离线泄露 | 备份加密、访问控制、定期恢复演练 |

考试问“如何保护用户隐私”，可以从采集最小化、传输加密、存储加密、展示脱敏、访问控制、审计日志、备份保护这些角度答。

### 认证机制比较

| 方式 | 优点 | 风险或限制 |
| --- | --- | --- |
| 用户名口令 | 实现简单 | 弱口令、撞库、泄露风险 |
| 短信验证码 | 用户体验较好 | SIM 卡风险、短信劫持、成本 |
| 多因素认证 | 安全性更高 | 使用复杂度增加 |
| 数字证书 | 身份可信度高 | 证书管理和部署成本 |
| Token | 适合前后端分离和移动端 | 令牌泄露后需过期、刷新、吊销机制 |

关键系统常采用多因素认证，例如口令加短信、口令加动态令牌。

### 接口安全答题模板

公网接口安全可以按固定层次写：

1. 身份认证：确认调用方身份，例如 Token、证书、AppKey。
2. 权限控制：校验调用方是否有访问该接口和数据的权限。
3. 传输加密：使用 HTTPS/TLS 防窃听。
4. 参数签名：防止请求参数被篡改。
5. 时间戳和 Nonce：防止重放。
6. 限流和黑名单：防止刷接口和暴力攻击。
7. 日志审计：记录调用方、时间、参数摘要、结果和异常。

### 安全题常见失分点

- 只写“登录验证”，没有写授权和数据权限。
- 只写“加密”，没有区分传输加密和存储加密。
- 只写“签名”，没有写时间戳和 Nonce，不能防重放。
- 只写“前端隐藏按钮”，没有写后端接口鉴权。
- 审计日志记录敏感明文，反而造成数据泄露。
