# 大数据架构

> 重要程度：P1  
> 考纲定位：案例分析典型架构之一，关注数据采集、存储、处理、分析和治理。

## 优先掌握

1. 大数据 5V 特征和典型处理链路。
2. 离线处理、实时处理、批处理、流处理的区别。
3. 数据仓库、数据湖、湖仓一体的边界。
4. 数据治理：质量、标准、血缘、安全、生命周期。

## 概念和场景

| 重要度 | 内容 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | 5V | 量大、速度快、类型多、价值密度低、真实性要求高 | 日志、交易、位置、图片等多源数据汇总分析 |
| P0 | 数据采集 | 从业务系统、日志、设备采集数据 | 订单库 CDC 同步到数据平台 |
| P0 | 离线处理 | 周期性处理历史数据 | 每晚统计昨日销售报表 |
| P0 | 实时处理 | 低延迟处理持续到达的数据 | 实时风控识别异常交易 |
| P0 | 数据仓库 | 面向主题和分析的结构化数据体系 | 统一销售、客户、商品指标口径 |
| P1 | 数据湖 | 存储原始、多类型数据 | 原始日志、图片、半结构化数据先入湖 |
| P1 | 数仓分层 | ODS、DWD、DWS、ADS 等逐层加工 | 原始订单进入 ODS，汇总成销售主题指标 |
| P1 | 数据治理 | 保证数据可用、可信、可管 | 建数据标准、质量规则、血缘和权限 |

## 架构链路

1. 数据源：业务库、日志、文件、设备、第三方数据。
2. 采集：批量导入、CDC、消息流、日志采集。
3. 存储：分布式文件、对象存储、数据仓库、搜索引擎。
4. 计算：离线批处理、实时流处理、交互式查询。
5. 服务：报表、指标平台、画像、推荐、风控。
6. 治理：标准、质量、安全、血缘、生命周期贯穿全链路。

## 处理模式选择

| 场景 | 选择 |
| --- | --- |
| 日报、月报 | 离线批处理。 |
| 实时告警、实时风控 | 流处理。 |
| 历史趋势分析 | 数据仓库或 OLAP。 |
| 多类型原始数据沉淀 | 数据湖。 |
| 既要湖的灵活又要仓的治理 | 湖仓一体。 |

## 易混点

| 易混项 | 区分 |
| --- | --- |
| ETL vs ELT | ETL 先转换再入库；ELT 先入库再利用平台计算转换。 |
| OLTP vs OLAP | OLTP 处理交易；OLAP 支持分析。 |
| 数据质量 vs 数据标准 | 数据标准定义口径；数据质量检查数据是否符合口径。 |

## 考纲外重要保留

具体组件如 Hadoop、Spark、Flink、Hive、Kafka 只作为常见实现名词保留；案例题优先写链路、处理模式和治理能力。
