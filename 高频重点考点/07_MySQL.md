# MySQL

> 重要程度：P0  
> 考纲定位：关系数据库、数据库性能、高可用和数据安全的工程化落点。

## 优先掌握

1. 索引、联合索引、覆盖索引和索引失效。
2. 事务 ACID、隔离级别和锁冲突。
3. 主从复制、读写分离、主从延迟。
4. 分库分表、深分页、慢查询优化。

## 概念和场景

| 重要度 | 内容 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | B+Tree 索引 | 用有序树结构减少扫描范围 | 按订单号查询可直接定位，不必全表扫描 |
| P0 | 联合索引 | 多列组成一个索引，遵守最左前缀 | `(user_id, status, create_time)` 适合按用户和状态查订单 |
| P0 | 覆盖索引 | 查询列都在索引中，减少回表 | 列表页只查 id、状态、时间，可直接走索引 |
| P0 | 事务 | 保证一组数据变更的一致性 | 创建订单、扣减余额、写流水必须一起成功或回滚 |
| P0 | 隔离级别 | 控制并发事务互相可见程度 | 高并发库存扣减要避免脏读、不可重复读或幻读影响 |
| P0 | 主从复制 | 主库写入，从库复制数据 | 读请求分散到从库，但要处理复制延迟 |
| P1 | 执行计划 | 查看 SQL 如何访问表和索引 | `type` 很差、扫描行数大时要优化索引或 SQL |
| P1 | 深分页 | 大 offset 导致扫描大量无用行 | 用游标或上一页最大 id 替代 `limit 100000,20` |
| P1 | 分库分表 | 按规则拆分数据 | 订单按用户 id 分片，查询必须带分片键 |

## SQL 优化顺序

1. 明确查询条件、排序字段和返回列。
2. 看是否能命中合适索引，避免函数、隐式转换、前导模糊匹配导致失效。
3. 控制返回列，能覆盖索引就少回表。
4. 大表分页改成基于游标或业务锚点。
5. SQL 和索引都无法解决时，再考虑缓存、读写分离、分区或分片。

## 高可用答题点

| 问题 | 处理 |
| --- | --- |
| 主库故障 | 主从复制、自动切换、故障检测、应用重连。 |
| 主从延迟 | 关键读走主库、延迟监控、半同步、业务补偿。 |
| 单表过大 | 分区、归档、分库分表、冷热分离。 |
| 数据误删 | 备份、binlog、恢复演练、权限控制。 |

## 易混点

| 易混项 | 区分 |
| --- | --- |
| 索引多 vs 查询快 | 索引能加速读，但会增加写入和维护成本。 |
| 读写分离 vs 分库分表 | 读写分离解决读压力；分库分表解决容量和单点压力。 |
| ACID vs CAP | ACID 是单数据库事务特性；CAP 是分布式系统取舍。 |
