# 嵌入式与物联网

## 考试中一般怎么考

1. 架构识别：根据传感器、网关、云平台、移动端判断物联网分层架构。
2. 质量属性：问实时性、可靠性、功耗、安全和资源受限如何影响设计。
3. 通信协议：比较 MQTT、HTTP、CoAP、蓝牙、ZigBee、LoRa、NB-IoT、Modbus、CAN 等适用场景。
4. 边缘计算：问为什么在网关或边缘节点预处理数据。
5. 设备管理：问设备注册、认证、升级、监控、告警、设备影子和远程维护。
6. 嵌入式设计：问任务划分、硬件抽象、中断、实时调度、任务通信和可靠性设计。
7. 物联网安全：问设备、通信、平台、应用和数据各层如何防护。

## 针对考法梳理知识点

### 物联网典型分层

物联网系统通常可以分为：

1. 感知层：传感器、控制器、摄像头、RFID，负责采集和执行。
2. 网络层：蜂窝网络、Wi-Fi、蓝牙、ZigBee、LoRa、以太网，负责传输。
3. 平台层：设备接入、消息处理、规则引擎、数据存储、设备管理。
4. 应用层：监控大屏、移动 App、业务系统、告警和报表。

考试给出“传感器采集、网关上传、平台分析、用户查看”时，可以按这四层组织答案。

### 三层和四层架构口径

物联网架构常见两种口径：

| 口径 | 分层 |
| --- | --- |
| 三层架构 | 感知层、网络层、应用层 |
| 四层架构 | 感知层、网络层、平台层、应用层 |

三层架构中的应用层通常把平台能力和业务应用合在一起说。四层架构把设备接入、消息处理、数据存储、规则引擎、设备管理单独作为平台层。

答题时按题干口径展开。如果题目出现“物联网平台、设备管理、规则引擎”，更适合按四层回答。

### 传感器、执行器和网关

| 组件 | 职责 |
| --- | --- |
| 传感器 | 采集温度、湿度、位置、压力、图像等现场数据 |
| 执行器 | 执行控制动作，例如开关阀门、启动电机、调节灯光 |
| 网关 | 协议转换、设备汇聚、边缘计算、安全接入、本地缓存 |

传感器回答“感知什么”，执行器回答“控制什么”，网关回答“如何接入和管理大量异构设备”。

### 工业物联网特点

工业物联网比普通消费物联网更强调确定性、可靠性和安全隔离。

常见特点：

- 实时性和确定性要求高，控制指令不能长时间延迟。
- 设备生命周期长，新旧协议并存。
- 现场环境复杂，网络可能不稳定。
- 停机成本高，要求高可靠和可维护。
- 工业控制网络和办公网络需要隔离。
- 安全风险可能影响生产安全和人身安全。

工业场景中，关键控制逻辑通常应在设备或边缘网关本地闭环，云端更适合监控、分析、优化和集中管理。

### 嵌入式系统约束

嵌入式系统常见约束：

- CPU、内存、存储资源有限。
- 功耗敏感，电池设备要考虑休眠和低功耗通信。
- 实时性要求高，控制类任务不能长时间阻塞。
- 可靠性要求高，现场设备维护成本高。
- 网络不稳定，需要断点续传、缓存和重试。

因此设计时常用轻量协议、边缘预处理、本地缓存、看门狗、OTA 升级和远程诊断。

### 实时性

实时性关注任务必须在规定时间内完成。

硬实时系统错过截止时间会造成严重后果，例如工业控制、汽车制动。

软实时系统允许偶尔延迟，但会影响体验或服务质量，例如视频监控、环境数据采集。

如果题目强调“毫秒级响应”“控制指令必须及时执行”，答题要写 RTOS、任务优先级、中断处理、实时调度和本地闭环控制。

### RTOS

RTOS 是实时操作系统，适合资源受限且有实时任务调度要求的嵌入式设备。

常见作用：

- 任务调度。
- 中断管理。
- 定时器。
- 任务间通信。
- 资源互斥。

它和通用操作系统的重点不同：RTOS 更关注确定性响应和实时调度。

### 实时调度

实时调度关注任务能否在截止时间前完成。

常见调度方式：

| 调度 | 说明 |
| --- | --- |
| 抢占式调度 | 高优先级任务可打断低优先级任务 |
| 非抢占式调度 | 当前任务主动让出 CPU 后才切换 |
| 优先级调度 | 按任务优先级调度，实时任务通常优先级高 |
| 时间片轮转 | 多任务按时间片轮流运行，公平性较好 |
| RMS | 速率单调调度，周期越短优先级越高 |
| EDF | 最早截止期优先，截止时间越近优先级越高 |

考试一般不要求推导算法，重点是能说明实时任务要设置优先级、避免长时间阻塞，并通过调度策略保证截止时间。

### 中断处理原则

中断用于快速响应外部事件，例如传感器触发、串口接收、定时器到期。

设计原则：

- 中断服务程序 ISR 要短小快速。
- 耗时处理放到后台任务或工作队列。
- 中断中避免复杂计算、长时间循环和阻塞等待。
- 共享数据要用临界区、互斥或原子操作保护。
- 合理设置中断优先级，避免低优先级任务影响关键控制。

易错点：不能在中断里做大量业务处理，否则会影响系统实时性和其他中断响应。

### 任务间通信和同步

RTOS 中多个任务之间需要通信和同步。

| 机制 | 作用 |
| --- | --- |
| 信号量 | 通知事件发生或控制资源数量 |
| 互斥锁 | 保护共享资源，防止并发访问冲突 |
| 消息队列 | 在任务之间传递消息或数据 |
| 事件标志 | 表示一个或多个事件状态 |
| 邮箱 | 传递一个消息、指针或小块数据 |

选择时看数据量、实时性和同步关系。共享资源要避免死锁、优先级反转和长时间占用锁。

### 嵌入式软件架构设计

嵌入式软件常按硬件相关性和业务职责分层：

| 层次 | 职责 |
| --- | --- |
| 硬件抽象层 | 屏蔽芯片、传感器、接口差异 |
| 驱动层 | 控制 GPIO、串口、总线、网络模块 |
| 系统服务层 | 调度、定时器、任务通信、存储、日志 |
| 业务控制层 | 采集、控制、告警、状态机 |
| 通信层 | 协议适配、数据上报、命令下发 |

常见设计要点：

- 高实时任务用中断、优先级和实时调度保证截止时间。
- 耗时处理放到后台任务，避免阻塞中断和控制链路。
- 硬件访问通过抽象接口封装，便于更换芯片或传感器。
- 关键控制逻辑用状态机，避免状态跳转混乱。
- 通过看门狗、掉电保护、异常重启和日志提高可靠性。

易错点：嵌入式设计不能只写“上云”。现场控制、实时响应和异常保护通常必须在设备或网关本地完成。

### 嵌入式和普通软件区别

| 对比 | 嵌入式软件 | 普通应用软件 |
| --- | --- | --- |
| 资源 | CPU、内存、存储受限 | 资源通常更充足 |
| 硬件依赖 | 强依赖芯片、传感器、总线和外设 | 硬件相关性较弱 |
| 实时性 | 常有明确响应时限 | 多数关注吞吐和用户体验 |
| 可靠性 | 现场维护困难，故障影响大 | 可通过服务端快速修复 |
| 功耗 | 电池设备功耗敏感 | 通常不是首要约束 |
| 升级 | OTA 和现场升级风险高 | 软件发布和回滚更容易 |

答题时要突出资源受限、硬件相关、实时性、功耗、可靠性和维护困难。

### 嵌入式可靠性设计

| 风险 | 设计措施 |
| --- | --- |
| 程序跑飞或死锁 | 看门狗复位、异常检测 |
| 掉电导致数据损坏 | 掉电保护、事务化写入、关键数据备份 |
| 通信数据错误 | CRC 校验、重传、序号和确认机制 |
| 传感器异常 | 数据范围校验、冗余采样、故障告警 |
| 控制异常 | 安全状态、限位保护、人工接管 |
| 升级失败 | 双分区、版本回滚、签名校验 |
| 现场故障难定位 | 本地日志、远程诊断、运行状态上报 |

可靠性题不要只写“提高稳定性”，要说明故障如何发现、如何隔离、如何恢复到安全状态。

### 边缘计算和网关

网关常用于协议转换、设备接入、数据汇聚、边缘计算和安全隔离。

边缘计算把部分处理放在靠近设备的位置，减少上传数据量和云端压力，降低网络延迟。

适合场景：

- 网络不稳定，需要本地自治。
- 数据量大，全部上传成本高。
- 实时控制要求高，不能依赖云端往返。
- 需要本地过滤、聚合、异常检测。

### 边缘计算和云计算对比

| 对比 | 边缘计算 | 云计算 |
| --- | --- | --- |
| 位置 | 靠近设备和现场 | 集中云平台 |
| 优势 | 低延迟、本地自治、节省带宽 | 计算和存储能力强、全局分析、集中管理 |
| 适用 | 实时控制、弱网、数据预处理 | 大数据分析、模型训练、跨区域管理 |
| 风险 | 边缘节点资源有限、运维分散 | 网络依赖强、实时性受链路影响 |

常见组合：边缘侧负责采集、过滤、告警和本地控制；云端负责全局存储、分析、模型训练、设备管理和业务应用。

### 数据处理链路

物联网数据处理通常是：

```text
采集 -> 校验 -> 过滤 -> 聚合 -> 压缩 -> 上报 -> 存储 -> 分析 -> 告警 -> 可视化
```

设计要点：

- 采集侧要带设备编号和时间戳。
- 边缘侧可过滤噪声、聚合数据、压缩报文。
- 平台侧要处理乱序、重复、缺失和异常数据。
- 告警规则要避免频繁误报，可设置阈值、窗口和去抖动。

### 通信协议速查

| 协议 | 特点 | 适用场景 |
| --- | --- | --- |
| MQTT | 轻量发布订阅，适合弱网 | 设备上报、消息推送 |
| HTTP | 通用性强，开发简单 | 资源较充足、交互不频繁 |
| CoAP | 面向受限设备的轻量协议 | 低功耗、资源受限设备 |
| 蓝牙 | 短距离、低功耗 | 穿戴设备、近场连接 |
| ZigBee | 低功耗、自组网 | 智能家居、传感网络 |
| LoRa | 远距离、低功耗、低速率 | 农业、抄表、环境监测 |
| NB-IoT | 蜂窝物联网，广覆盖、低功耗、低速率 | 水表、电表、井盖、停车 |
| 5G | 高带宽、低延迟、广连接 | 车联网、工业控制、高清视频 |
| RFID / NFC | 近距离识别 | 资产识别、门禁、支付 |
| Modbus | 工业现场常见主从协议 | PLC、仪表、工业设备 |
| CAN | 抗干扰强，适合车载和工业总线 | 汽车电子、工业控制 |
| OPC UA | 工业互联和设备数据建模 | 工业平台、跨厂商设备集成 |

### MQTT 细化

MQTT 是物联网常用轻量消息协议，采用发布订阅模型。

核心概念：

- Broker：消息代理，负责接收和转发消息。
- Topic：主题，设备按主题发布或订阅消息。
- 发布者：发送消息的一方。
- 订阅者：接收某个主题消息的一方。

QoS 等级：

| 等级 | 含义 | 特点 |
| --- | --- | --- |
| QoS 0 | 最多一次 | 开销小，可能丢消息 |
| QoS 1 | 至少一次 | 不丢但可能重复，需要幂等 |
| QoS 2 | 只有一次 | 可靠性最高，交互开销最大 |

其他常见机制：

- 保留消息：Broker 保存某主题最后一条消息，新订阅者可立即获取状态。
- 遗嘱消息：设备异常断开时，由 Broker 发布离线通知。
- 心跳：维持连接并判断设备是否在线。

考试问“为什么物联网常用 MQTT”，可答：轻量、发布订阅解耦、适合弱网和大量设备连接，并支持 QoS、心跳和遗嘱消息。

### 安全和设备管理

物联网安全不能只保护云端，还要覆盖设备、传输和平台。

常见措施：

- 设备唯一身份和证书。
- 设备接入认证。
- 通信加密。
- 固件签名和安全启动。
- OTA 升级和版本回滚。
- 设备日志、监控、告警和远程诊断。

设备被盗、固件被篡改、弱口令、明文传输、默认密钥复用都是常见风险点。

### 物联网安全分层

| 层次 | 风险 | 措施 |
| --- | --- | --- |
| 设备安全 | 设备被仿冒、固件被篡改 | 唯一身份、安全启动、固件签名、安全芯片 |
| 通信安全 | 明文传输、重放、劫持 | TLS/DTLS、证书、签名、时间戳和随机数 |
| 平台安全 | 非法接入、越权控制 | 设备认证、访问控制、租户隔离、审计 |
| 应用安全 | 账号泄露、越权操作 | 认证授权、最小权限、操作审计 |
| 数据安全 | 敏感数据泄露、篡改 | 加密存储、脱敏、完整性校验、备份 |

物联网安全要特别防止“伪造设备接入”和“非法命令下发”，因为它可能直接影响现场设备和人员安全。

### 设备生命周期管理

物联网平台通常要管理设备全生命周期：

1. 设备注册：为设备分配唯一标识。
2. 设备认证：通过证书、密钥或安全芯片确认身份。
3. 设备接入：建立连接，选择协议和主题。
4. 状态监控：在线、离线、故障、电量、信号强度。
5. 远程配置：下发参数和策略。
6. OTA 升级：远程升级固件，失败可回滚。
7. 注销和报废：设备退役后吊销凭证。

考试问“如何管理大量设备”，可以按这个生命周期展开。

### OTA 升级细化

OTA 是远程升级设备固件或软件。

可靠 OTA 常见机制：

- 分包下载，减少弱网下失败成本。
- 断点续传，网络恢复后继续下载。
- 固件签名和完整性校验，防止篡改。
- 灰度升级，先升级少量设备观察效果。
- A/B 双分区或备份分区，升级失败可回滚。
- 升级前检查电量、网络和存储空间。
- 升级过程和结果上报平台，便于监控和追踪。

OTA 题要写“安全校验 + 失败回滚 + 灰度监控”，否则容易漏关键风险。

### 设备影子 / 数字孪生

设备影子用于在平台保存设备的最新状态和期望配置，即使设备离线，平台也能记录期望状态。

常见作用：

- 保存设备上报的最新状态，例如在线状态、电量、温度、固件版本。
- 保存平台期望下发的配置，例如采样周期、阈值、开关状态。
- 设备上线后同步期望配置。
- 应用不必直接依赖设备实时在线。

数字孪生更强调对物理设备或系统的数字化建模、状态映射、仿真和优化。考试中简单理解为“用数字模型反映真实设备状态和行为”即可。

### 数据上报和命令下发

物联网通信通常分为设备上报和平台下发。

设备上报关注：

- 采样频率。
- 数据过滤和压缩。
- 断网缓存和补传。
- 时间戳和设备编号。
- 异常数据告警。

命令下发关注：

- 指令是否需要确认。
- 超时和重试。
- 指令幂等，避免重复执行。
- 本地安全校验，避免非法控制。
- 关键控制指令可审计。

### 弱网和离线处理

设备现场网络经常不稳定。

常见设计：

- 本地缓存数据，网络恢复后补传。
- 使用轻量协议，减少报文开销。
- 关键控制逻辑本地闭环，不完全依赖云端。
- 消息确认和重试，避免数据丢失。
- 上报心跳，平台判断设备在线状态。

如果题目强调“偏远地区、网络不稳定、设备不能停”，应写边缘自治、本地缓存、断点续传和告警。

### 功耗设计

低功耗设备常见策略：

- 降低采样频率。
- 批量上报数据，减少通信次数。
- 休眠唤醒机制。
- 选择低功耗通信协议。
- 本地过滤无效数据，减少上传。

功耗和实时性往往冲突：采样越频繁、连接越常在线，实时性越好，但功耗越高。

```text
感知层通过传感器采集数据，网络层通过 MQTT/LoRa/蜂窝网络上传到网关或平台，平台层完成设备接入、认证、消息处理、数据存储、规则告警和设备管理，应用层提供监控、报表和业务联动。为满足实时性和弱网要求，可在边缘网关进行协议转换、数据过滤、本地缓存和本地控制；为满足安全性，应进行设备身份认证、通信加密、固件签名、OTA 升级和审计。
```
