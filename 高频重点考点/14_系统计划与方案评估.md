# 系统计划与方案评估

> 重要程度：P1  
> 考纲定位：系统规划、方案比较、可行性分析和建设实施。

## 优先掌握

1. 可行性分析：技术、经济、操作、法律和进度。
2. 方案评估：目标、指标、权重、评分、风险。
3. 新旧系统迁移：并行、试点、灰度、回滚、数据迁移。
4. 风险识别和应对。

## 概念和场景

| 重要度 | 内容 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | 技术可行性 | 技术方案能否实现目标 | 团队是否具备微服务和容器平台建设能力 |
| P0 | 经济可行性 | 成本收益是否合理 | 自建机房和上云方案比较投入、运维和扩容成本 |
| P0 | 操作可行性 | 用户和组织能否接受 | 业务人员是否能适应新审批流程 |
| P0 | 法律合规 | 是否满足法规和标准 | 个人信息处理是否满足合规要求 |
| P0 | 方案评估 | 多方案按指标比较 | A 方案性能好但成本高，B 方案改造小但扩展弱 |
| P1 | TCO | 总拥有成本 | 不只看采购价，还看运维、人力、升级和迁移成本 |
| P1 | ROI | 投资回报 | 新系统节省人力、提升收入或降低风险 |
| P1 | 试点先行 | 小范围验证后推广 | 先在一个分公司上线，稳定后全国推广 |

## 方案评估答题顺序

1. 确定评价目标和约束。
2. 建立指标：功能满足度、性能、可用性、安全、可扩展性、成本、周期、风险。
3. 给权重和评分，说明评分依据。
4. 比较方案优缺点，选择最符合目标的方案。
5. 给出风险控制和实施路线。

## 新旧系统迁移

| 问题 | 处理 |
| --- | --- |
| 业务不能中断 | 并行运行、灰度切换、回滚预案。 |
| 数据质量差 | 清洗、校验、试迁移、对账。 |
| 用户不熟悉 | 培训、试点、反馈改进。 |
| 外部接口多 | 适配层、兼容接口、分阶段替换。 |
| 风险不可控 | 分批上线、设置里程碑和验收标准。 |

## 易混点

| 易混项 | 区分 |
| --- | --- |
| 可行性分析 vs 方案评估 | 可行性判断能不能做；方案评估判断哪种做法更合适。 |
| TCO vs 初始成本 | TCO 包括建设、运行、维护、升级和退出成本。 |
| 试点 vs 灰度 | 试点偏组织范围验证；灰度偏上线流量和版本控制。 |

## 边界

不展开项目管理计算题和财务模型；案例题主要考比较维度、风险和实施策略。
