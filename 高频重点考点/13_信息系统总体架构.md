# 信息系统总体架构

> 重要程度：P1  
> 考纲定位：信息系统架构、行业特点、总体规划和架构设计文档。

## 优先掌握

1. 总体架构通常包括业务、应用、数据、技术、安全、运维。
2. 架构设计要从业务目标、约束和质量属性出发。
3. 能给出现状问题、目标架构、演进路线和治理机制。
4. 能把公共能力、标准规范和集成关系写清楚。

## 概念和场景

| 重要度 | 架构视角 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | 业务架构 | 业务能力、流程、组织和规则 | 政务服务按事项、部门、审批流程梳理 |
| P0 | 应用架构 | 应用系统、模块和服务关系 | 统一门户、业务办理、审批、报表系统如何协作 |
| P0 | 数据架构 | 数据主题、主数据、数据流和治理 | 企业客户、产品、订单数据统一口径 |
| P0 | 技术架构 | 技术平台、部署、网络和中间件 | 应用部署在容器平台，使用数据库和消息队列 |
| P0 | 安全架构 | 身份、权限、边界、数据保护 | 外网访问进 DMZ，核心数据在内网加密存储 |
| P1 | 运维架构 | 监控、日志、告警、备份和恢复 | 交易异常时能定位服务、数据库和消息积压 |
| P1 | 标准规范 | 接口、数据、日志、开发和运维标准 | 所有系统统一用户编码、接口返回格式和审计字段 |

## 总体架构答题顺序

1. 先概括现状问题：烟囱系统、数据孤岛、接口混乱、性能不足、安全薄弱。
2. 再给目标架构：业务协同、应用分层、数据共享、技术支撑、安全保障。
3. 再说明关键机制：统一门户、统一身份、主数据、服务集成、监控运维。
4. 最后给实施路线：试点、迁移、并行运行、灰度切换、持续治理。

## 常见问题与改进

| 问题 | 改进 |
| --- | --- |
| 系统烟囱 | 梳理应用边界，建设公共能力和统一集成。 |
| 数据孤岛 | 建主数据和数据标准，设计数据交换和共享机制。 |
| 重复建设 | 抽取统一认证、消息、报表、流程等公共能力。 |
| 接口混乱 | 制定接口规范、版本策略、网关治理。 |
| 运维不可见 | 建日志、指标、链路追踪、告警和应急流程。 |

## 易混点

| 易混项 | 区分 |
| --- | --- |
| 应用架构 vs 技术架构 | 应用架构描述业务系统和服务关系；技术架构描述支撑这些系统的技术平台。 |
| 数据架构 vs 数据库设计 | 数据架构关注数据主题、流动、治理和共享；数据库设计关注表、关系和存储。 |
| 总体架构 vs 详细设计 | 总体架构定方向、边界和关键机制；详细设计落到类、接口、表和流程。 |

## 边界

不展开企业架构框架的完整方法论；案例题只需把视角、问题、措施和落地顺序写清。
