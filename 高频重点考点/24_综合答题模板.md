# 综合答题模板

> 重要程度：P2  
> 考纲定位：案例分析作答组织，不是独立考点，用于把各章知识落成答案。

## 优先掌握

1. 先读题干目标和约束，再选技术。
2. 回答要包含“问题、原因、措施、效果、风险”。
3. 方案题要写取舍，不要只罗列技术名词。
4. 图题、评估题、改进题要用不同答题框架。

## 通用分析框架

| 步骤 | 作用 | 场景式解释 |
| --- | --- | --- |
| 识别目标 | 找业务目标和质量属性 | “高峰期不中断”对应可用性，“查询慢”对应性能 |
| 识别约束 | 找不能突破的条件 | 必须兼容旧系统、不能停机、必须内网部署 |
| 定位问题 | 找当前架构缺陷 | 单点、耦合、数据孤岛、缺少监控 |
| 选择措施 | 用架构机制解决问题 | 缓存、异步、分层、冗余、网关、安全控制 |
| 说明代价 | 写清副作用和风险 | 异步带来最终一致，分库分表带来路由复杂度 |
| 验证结果 | 写可度量指标 | 压测、监控、对账、演练、响应时间和可用率 |

## 常用模板

### 架构改进题

1. 当前问题是：单点、耦合、性能瓶颈、数据不一致、安全薄弱或运维不可见。
2. 原因是：职责边界不清、同步链路过长、缺少冗余、缺少治理或缺少标准。
3. 改进措施是：按问题选择分层、服务化、缓存、异步、冗余、安全、监控等。
4. 预期效果是：提升对应质量属性。
5. 风险和配套措施是：一致性、复杂度、成本、迁移和回滚。

### 方案选择题

1. 列出约束和评价指标。
2. 比较每个方案的优势、劣势和风险。
3. 选择最符合核心目标的方案。
4. 给出补偿措施处理短板。

### 架构评估题

1. 提取质量属性场景。
2. 识别架构决策。
3. 判断敏感点、权衡点和风险点。
4. 给出改进建议和验证方式。

### 图题

1. 先判图类型。
2. 再找边界、角色、对象、数据流或调用关系。
3. 按题干名词和动词补缺。
4. 检查方向、层次、平衡和名称一致。

## 常见失分点

| 失分点 | 修正 |
| --- | --- |
| 只写技术名词 | 补充解决的问题和适用场景。 |
| 不写约束 | 回答前先引用题干限制。 |
| 不写代价 | 对分布式、缓存、异步、分库分表都写副作用。 |
| 把综合知识背诵当案例答案 | 用题干场景组织答案。 |
| 图题忽略一致性 | 检查父子图、实体关系、消息顺序和命名。 |
