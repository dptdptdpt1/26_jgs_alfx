# 云原生与容器化

> 重要程度：P1  
> 考纲定位：新版教程案例分析中的典型架构，通常和微服务、高可用、DevOps 结合。

## 优先掌握

1. 云原生的核心目标：弹性、自动化、可观测、快速交付。
2. 容器、镜像、编排、服务发现、配置和密钥管理。
3. Kubernetes 的核心对象和高可用能力。
4. 容器化改造的收益、风险和适用边界。

## 概念和场景

| 重要度 | 内容 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | 容器 | 应用和依赖打包运行的隔离环境 | 同一镜像在测试和生产环境一致运行 |
| P0 | 镜像 | 容器运行模板 | 发布新版本时构建订单服务镜像 |
| P0 | 编排 | 管理容器部署、扩缩容和恢复 | 节点故障后自动在其他节点拉起实例 |
| P0 | Service | 为一组实例提供稳定访问入口 | 订单服务多副本变动，调用方仍访问同一服务名 |
| P0 | Ingress | 管理外部 HTTP 入口 | 外部流量按域名路由到不同服务 |
| P1 | ConfigMap/Secret | 管理配置和敏感信息 | 数据库地址用配置，密码用 Secret |
| P1 | 弹性伸缩 | 根据负载增减实例 | 流量升高时自动扩容支付查询服务 |
| P1 | 可观测性 | 日志、指标、链路追踪 | 快速定位容器重启、接口慢或资源不足 |

## 容器化改造答题顺序

1. 评估应用是否适合容器化：无状态优先，状态组件谨慎。
2. 标准化镜像构建和配置外置。
3. 用编排平台管理部署、扩缩容、健康检查和故障恢复。
4. 配套 CI/CD、灰度发布、监控告警和日志采集。
5. 说明风险：状态数据、网络、存储、安全、运维能力。

## 发布策略

| 策略 | 适用场景 |
| --- | --- |
| 滚动发布 | 普通版本升级，逐步替换实例。 |
| 蓝绿发布 | 需要快速整体切换和回滚。 |
| 灰度发布 | 新版本风险不确定，先放小流量验证。 |
| 金丝雀发布 | 面向少量用户或少量实例试运行。 |

## 易混点

| 易混项 | 区分 |
| --- | --- |
| 容器 vs 虚拟机 | 容器共享宿主内核、启动快；虚拟机隔离更重。 |
| Docker vs Kubernetes | Docker 偏容器运行和镜像；Kubernetes 偏集群编排。 |
| 云原生 vs 上云 | 上云是部署位置变化；云原生是架构和交付方式变化。 |

## 考纲外重要保留

Service Mesh、Serverless 和 GitOps 作为扩展保留；案例题中只在题干明确出现时，从服务治理、弹性、自动化交付和复杂度角度回答。
