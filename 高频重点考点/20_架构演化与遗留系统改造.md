# 架构演化与遗留系统改造

> 重要程度：P2  
> 考纲定位：软件架构演化、维护和信息系统升级改造。

## 优先掌握

1. 遗留系统评估：业务价值、技术风险、维护成本、替换难度。
2. 改造策略：封装、替换、重构、迁移、退役。
3. 绞杀者模式、防腐层、并行运行、灰度切换。
4. 数据迁移、接口兼容、回滚和补偿。

## 概念和场景

| 重要度 | 内容 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | 遗留系统评估 | 判断系统是否保留、改造或替换 | 老核心系统业务重要但技术陈旧，不能一次下线 |
| P0 | 封装 | 在旧系统外包一层接口 | 新系统通过 API 调用旧系统能力 |
| P0 | 渐进迁移 | 分阶段替换，降低风险 | 先迁移查询功能，再迁移交易功能 |
| P0 | 绞杀者模式 | 新系统逐步接管旧系统功能 | 新订单走新服务，历史订单仍由旧系统处理 |
| P1 | 防腐层 | 隔离旧系统模型和接口污染 | 新系统不直接依赖旧字段和旧流程 |
| P1 | 并行运行 | 新旧系统同时运行一段时间 | 对比新旧报表结果，确认一致后切换 |
| P1 | 回滚 | 切换失败后恢复到旧版本 | 新支付服务异常时流量切回旧服务 |

## 改造答题顺序

1. 评估现状：业务价值、技术债、数据质量、接口依赖、运行风险。
2. 确定目标：质量属性、业务能力、标准化、可维护性。
3. 选择策略：封装、重构、替换、迁移、退役或组合使用。
4. 设计迁移：接口兼容、数据迁移、灰度、并行、回滚。
5. 控制风险：监控、对账、培训、分阶段验收。

## 数据迁移要点

| 风险 | 控制 |
| --- | --- |
| 数据质量差 | 清洗、映射、去重、规则校验。 |
| 迁移窗口短 | 分批迁移、增量同步、停机窗口控制。 |
| 新旧口径不一致 | 建字段映射和转换规则。 |
| 切换失败 | 回滚预案、备份、双写或只读保护。 |

## 易混点

| 易混项 | 区分 |
| --- | --- |
| 重构 vs 重写 | 重构保留外部行为改善内部结构；重写是重新实现。 |
| 封装 vs 替换 | 封装让旧系统继续提供能力；替换逐步下线旧能力。 |
| 双写 vs 同步 | 双写是业务同时写新旧系统；同步可由日志、消息或批处理完成。 |

## 考纲外重要保留

云迁移中的 6R 策略作为扩展保留；案例题中可简化为保留、封装、重构、替换、迁移、退役。
