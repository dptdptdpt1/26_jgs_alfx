# 云原生与容器化

## 考试中一般怎么考

1. 容器化改造：问 Docker 解决什么问题，镜像、容器、仓库如何配合。
2. Kubernetes：问编排、服务发现、滚动升级、弹性伸缩、故障自愈。
3. DevOps：问 CI/CD、自动构建、自动测试、自动部署如何缩短交付周期。
4. 发布策略：比较灰度发布、蓝绿发布、滚动发布。
5. 云上高可用：问多可用区、自动伸缩、云数据库、对象存储如何提高可用性。

## 针对考法梳理知识点

### Docker

Docker 把应用及其运行依赖打包成镜像，容器基于镜像运行。

它解决的是环境不一致、部署复杂、迁移困难的问题。

常见概念：

- 镜像：只读模板，包含应用和依赖。
- 容器：镜像运行后的实例。
- 镜像仓库：存放和分发镜像。
- Dockerfile：定义镜像构建过程。

容器不是虚拟机。容器共享宿主机内核，启动更快、资源开销更小，但隔离性弱于虚拟机。

### Kubernetes

Kubernetes 用于容器编排，负责部署、调度、扩缩容、服务发现和故障恢复。

常见机制：

- Pod：最小调度单元，通常运行一个或多个紧密相关容器。
- Deployment：声明副本数量和升级策略。
- Service：为 Pod 提供稳定访问入口和负载均衡。
- ConfigMap/Secret：管理配置和敏感信息。
- HPA：根据 CPU、内存或自定义指标自动扩缩容。

考试问“为什么 K8s 提高可用性”，要写：副本机制、健康检查、故障自动拉起、滚动更新、服务发现和负载均衡。

### 弹性伸缩

弹性伸缩根据负载自动增加或减少实例。

它适合流量波动明显的系统，例如电商活动、在线教育开课、政务集中申报。

前提是应用尽量无状态，状态放到数据库、缓存或对象存储中。否则新增实例无法直接承接请求。

### DevOps 和 CI/CD

DevOps 强调开发、测试、运维协作，通过自动化流水线提高交付效率和质量。

CI/CD 常见流程：

1. 提交代码触发流水线。
2. 自动构建。
3. 自动执行单元测试、集成测试和静态检查。
4. 构建镜像或发布包。
5. 部署到测试、预发或生产环境。
6. 监控发布结果，失败时回滚。

它解决的是手工部署容易出错、反馈慢、版本不可追溯的问题。

### 灰度、蓝绿、滚动发布

| 发布方式 | 机制 | 优点 | 局限 |
| --- | --- | --- | --- |
| 灰度发布 | 先让少量用户或流量使用新版本 | 风险可控，便于验证 | 需要流量控制和监控 |
| 蓝绿发布 | 新旧两套环境并存，切换流量 | 回滚快，环境隔离好 | 资源成本较高 |
| 滚动发布 | 分批替换实例 | 资源成本低，过程平滑 | 新旧版本短期共存，需兼容 |

### 云上高可用

云上高可用常见组合：

- 多可用区部署，避免单机房故障。
- 负载均衡，把流量分发到多个实例。
- 自动伸缩，应对流量波动。
- 云数据库主备或多副本，提高数据可用性。
- 对象存储保存静态文件和备份。
- 监控告警和日志服务，及时发现异常。

考试答云架构时，不要只写“上云”。要说明计算、存储、网络、数据库和监控分别如何提升质量属性。

### Kubernetes 故障自愈细化

Kubernetes 的自愈能力来自声明式管理和控制循环。

常见机制：

- 副本数声明：期望运行 3 个副本，少了就自动拉起。
- 存活探针：容器异常时重启容器。
- 就绪探针：未准备好的 Pod 不接收流量。
- 节点故障迁移：节点不可用时，Pod 可调度到其他节点。
- 滚动更新：逐步替换旧版本实例，降低发布中断。

答题时注意：Kubernetes 能拉起进程和调度容器，但不能自动修复业务逻辑错误，应用仍要有监控、日志和回滚策略。

### 容器化改造注意点

不是所有系统直接打包成镜像就算云原生。

改造要点：

- 应用无状态化，把会话、文件、状态放到外部存储。
- 配置外置化，不把环境配置写死到镜像。
- 日志标准输出，便于平台收集。
- 健康检查接口，支持探针判断存活和就绪。
- 优雅停机，处理正在执行的请求。
- 镜像分层和精简，降低构建和拉取成本。

### 云数据库和自建数据库

云数据库由云平台托管备份、高可用、监控、扩容和补丁。

优点：

- 运维成本低。
- 主备、高可用、备份能力成熟。
- 可以按需扩容。
- 监控告警和恢复能力较完善。

限制：

- 成本和厂商绑定。
- 参数、插件、底层控制能力不如自建灵活。
- 跨云迁移需要评估兼容性和数据迁移成本。

### 发布策略选择

| 场景 | 建议 |
| --- | --- |
| 新版本风险高，只想让少量用户试用 | 灰度发布 |
| 需要快速回滚，资源允许两套环境 | 蓝绿发布 |
| 普通服务升级，资源有限 | 滚动发布 |
| 数据库结构有不兼容变更 | 先做兼容字段和双写，再灰度应用 |

发布题要补监控指标：错误率、响应时间、业务成功率、资源利用率。发现异常后要能自动或手动回滚。

### 云原生题常见失分点

- 只写 Docker，没有写镜像仓库、部署、配置和监控。
- 只写 Kubernetes，没有写 Service、Deployment、探针、滚动更新。
- 只写自动伸缩，没有说明应用必须无状态。
- 只写灰度发布，没有写流量比例、监控和回滚。
- 只写多可用区，没有写数据复制和故障切换。
