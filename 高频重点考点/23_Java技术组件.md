# Java 技术组件

> 重要程度：P2  
> 考纲定位：应用支撑技术、中间件和旧 J2EE 架构识图。部分内容属于旧体系重要保留。

## 优先掌握

1. J2EE 分层中 Web 容器、业务组件、数据访问和企业服务的位置。
2. Servlet、JSP、JavaBean、JDBC、JMS、JTA、JNDI 的职责。
3. 能看懂旧架构图，不把组件职责放错层。
4. EJB、RMI、JCA 等旧组件只保留识别级别。

## 概念和场景

| 重要度 | 组件 | 概念解释 | 场景式解释 |
| --- | --- | --- | --- |
| P0 | Servlet | 处理 HTTP 请求的 Java Web 组件 | 接收登录请求，调用业务服务后返回结果 |
| P0 | JSP | 服务器端页面技术 | 旧系统用 JSP 渲染查询页面 |
| P0 | JavaBean | 封装属性和简单逻辑的 Java 对象 | 页面表单数据封装成用户对象 |
| P0 | JDBC | Java 访问关系数据库的 API | 业务服务通过 JDBC 查询订单表 |
| P1 | JMS | Java 消息服务接口 | 订单成功后发送消息通知发货系统 |
| P1 | JTA | Java 分布式事务 API | 跨数据库或消息资源的事务协调 |
| P1 | JNDI | 命名和目录服务 | 应用通过名称查找数据源或 EJB |
| P2 | EJB | 企业级业务组件模型 | 旧系统把业务逻辑放在会话 Bean 中 |
| P2 | RMI | Java 远程方法调用 | 旧系统 Java 进程间远程调用对象方法 |
| P2 | JCA | 连接企业信息系统的连接器架构 | 应用服务器连接遗留系统资源 |

## J2EE 分层识图

1. 客户层：浏览器、客户端、外部系统。
2. Web 层：Servlet、JSP、控制器。
3. 业务层：业务服务、EJB、事务处理。
4. 集成层：JMS、JCA、WebService、适配器。
5. 数据层：数据库、目录服务、遗留系统。

## 答题要点

| 问法 | 回答 |
| --- | --- |
| 某组件放哪一层 | 先判断它处理界面、业务、消息、事务还是数据访问。 |
| 为什么用应用服务器 | 提供事务、连接池、安全、命名服务、消息等企业能力。 |
| 旧 J2EE 如何现代化 | 分层梳理、接口封装、逐步服务化、替换过重组件。 |

## 易混点

| 易混项 | 区分 |
| --- | --- |
| Servlet vs JSP | Servlet 偏请求控制；JSP 偏页面展示。 |
| JDBC vs JNDI | JDBC 访问数据库；JNDI 查找命名资源。 |
| JMS vs JTA | JMS 管消息；JTA 管事务。 |
| EJB vs JavaBean | EJB 是企业组件模型；JavaBean 是普通 Java 对象规范。 |

## 考纲外重要保留

EJB、RMI、JCA 在现代系统中低频，但旧题和 J2EE 架构图仍可能出现；本库只保留识图和职责级别，不展开开发细节。
